## Mapping Contract

| Feed value | Destination / rule |
| --- | --- |
| `description` | Existing bounded plain-text Summary, title fallback; never use it instead of a supplied full body. |
| `content:encoded` | Full source Description, with summary fallback. Source prose is retained even when it repeats or conflicts with explicit feed metadata. |
| `category`, legacy `job_function` | Existing category/keyword mapping. Broad job-function labels do not establish ISCO occupation or employer industry. |
| `price`, legacy `salary` | Exact raw cache text. Recognized ISO currency plus positive exact amount/range/explicit threshold map salary CFs and `Incentivized = true`. A single exact amount sets equal bounds; a threshold sets only the known bound and retains source wording. Missing salary maps disclosure No, not unpaid work. Ambiguous, zero, negative, reversed or unsupported text stays readable/unknown; no pay interval is inferred. |
| `work_type` | Full Time/Part Time map schedule. Explicit Contract maps Employment Type only. Other values remain in Description; never infer Permanent/FixedTerm, duration or working hours. |
| `experience_level` + `experience_length` | Use configured experience options only when labels and explicit year counts agree: Entry 1–3, Mid 4–6, Senior 7+. No Experience accepts missing length, the supplied no-experience label or zero years, but not a positive/unknown requirement. Contradictions/unsupported labels stay in Description. Precise length is always retained there. Legacy Difficulty is unchanged. |
| `minimum_qualification` | Explicit source-label map to existing Education GUIDs: high school to Secondary, Diploma/OND/HND to Tertiary Diploma, Degree to Bachelor, MBA/MSc to Master, PhD to PhD. Unknown/ambiguous qualifications remain in Description. HND/OND retain their exact text even when mapped to the broader Diploma lookup. |
| `location` | Retain exact free text in Description; do not infer precise city/region or new applicant-eligibility rules. Country remains feed-based. |

The salary parser accepts only a complete amount/range/recognized-threshold expression.
“Commission Only” remains unmapped; strict Above/Below wording is retained even with a mapped
bound. Currency and Education references must resolve before CF values are supplied. Salary pay
interval, employment duration, occupation and industry are neither inferred nor cleared by this mapper.

### Cross-provider authoritative CF snapshots

| Provider | Mapped-field policy |
| --- | --- |
| Jobberman | Eight owned keys: salary disclosed/minimum/maximum/currency, employment type, work schedule, experience level and qualification. The shared helper clears missing/unmappable mappings for only this subset. Pay interval/industry/duration remain outside its ownership. |
| JobJack | Six owned keys: salary disclosed/minimum/maximum/pay interval, work schedule and industry. The same helper clears withdrawn mappings; currency/qualification/employment type remain outside its ownership. |
| Alison | Learning difficulty is always explicitly mapped, including its existing AnyLevel fallback; no missing-key withdrawal gap. |
| IXO / Umuzi | Non-Job difficulty is always explicitly mapped, including the existing type-specific fallback. Job mappings do not claim those difficulty CFs. Unknown supplied source values fail rather than silently clearing data. |
| Verification responses / SAYouth push | No new completion-CF ownership or outbound CF mapping is introduced. A response supplying no CFs must not be treated as a full CF replacement. |

Only an explicitly authoritative field subset may opt into snapshot completion. Catalogue-level
completeness is not permission to clear every configured CF, and a partial/delta payload must
retain ordinary PATCH omission semantics. Keys outside the ownership set are preserved; neither
system/schema flags nor the global constants catalogue grant ownership. Defaults/replacements
are emitted explicitly rather than turned into deletion entries.
