## Gotchas

- `Active` is the only resumable state. The UI shows **Continue cash-out** only for an active, non-terminal payout and obtains a fresh hosted URL from the session endpoint.
- Although IXO can technically reopen a completed hosted session, Yoma deliberately treats `Completed` as final and exposes no resume action.
- Hosted URLs are short-lived and are never persisted as durable profile state.
- IXO keeps an unconfirmed payout active for 24 hours; confirmed processing may take up to six additional hours. Webhooks and reconciliation normally commit/release before the 30-hour ZLTO safety threshold.
- The payout provider is idempotent by Yoma payout transaction id. Replaying the same id with a different amount must return conflict.
- IXO's Test fiat delivery is simulated; an account ending in `9999` exercises its downstream delivery failure/refund journey after Yoma has already received `Completed`, so it does not reverse the ZLTO lifecycle.
