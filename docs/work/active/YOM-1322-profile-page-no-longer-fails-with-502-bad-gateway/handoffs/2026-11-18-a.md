## What Was Done

- Diagnosed Adrian's stage report (Jam `32dbe72d`): `502` with `server: awselb/2.0` on both the
  `/_next/data/…/user/profile.json` request and the full-page fallback at 08:12:59–08:13:00 SAST.
- Built a repro without stage access. Script (throwaway, lived at `/tmp/yoma-502-loop.sh`, deleted):
  take the `localhost` cookies from `src/web/e2e/.auth/<role>.json`, `curl -D` `/user/profile` on
  `pnpm dev`, count `Set-Cookie` lines and total header bytes, red if > 32 768.
  - Before fix: youth 10 lines / 27 043 B, admin 10 / 27 628 B, **orgAdmin 10 / 32 908 B → over the
    ALB limit**. Every copy is the same `next-auth.session-token.0` + `.1` pair.
  - After fix: 2 lines / 5 585–6 760 B for all three roles; all four prefetched queries
    (`genders`, `countries`, `educations`, `userProfile`) dehydrate, so the Bearer token still reaches the API.
- Mechanism (confirmed in `node_modules/next-auth/next/utils.js` `setCookie`): each `getServerSession`
  call re-encodes the JWT and pushes another `Set-Cookie` onto the response. `ApiServer(context)` was
  calling it once per axios instance, i.e. once per service call. Profile page = 1 (page) + 4 (prefetches).
- Fix: `getServerAuthSession(ctx)` in `src/web/src/server/auth.ts` memoises the promise per `ctx.req`
  (`WeakMap`); `src/web/src/lib/axiosServer.ts` and all 42 page `getServerSideProps` use it. Codemod via
  ast-grep; three pages it could not parse (`opportunities/actionLink/verify/[linkId]`,
  `organisations/dashboard`, `referrals/index`) were edited by hand.
- Found the 2024 precedent: [YOM-176](https://linear.app/didx/issue/YOM-176) — Robbie identified the same
  32 K ALB header limit then; mitigation was infra-side (internal ALB → NLB). The public ALB still enforces it.

## Gotchas

- The saved e2e sessions in `src/web/e2e/.auth/*.json` go stale (Keycloak refresh fails after a few days);
  `E2E_WARMUP=0 npx playwright test --project=setup` refreshes them. With a stale session the page still
  renders but `userProfile` is not dehydrated (API 401) — that is pre-existing, not from this change.
- The dev server needs `keycloak` to resolve to `127.0.0.1` (`/etc/hosts`) for token refresh; otherwise
  every `getServerSession` waits on a 10 s connect timeout and `/user/profile` takes minutes.
- Header size scales with the Keycloak token, so a youth account can be green locally while an org admin
  is red. Stage tokens carry the `__Secure-` prefix and `; Secure` on top.
- `getServerAuthSession` existed already (unused) — it is now the only sanctioned way to read the session
  server-side. A page that calls `getServerSession` directly again reintroduces a second cookie copy.
