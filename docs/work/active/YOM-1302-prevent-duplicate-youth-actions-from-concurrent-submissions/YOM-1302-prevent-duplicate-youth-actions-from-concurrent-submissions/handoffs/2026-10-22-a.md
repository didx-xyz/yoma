## Gotchas

- This is concurrency mitigation, not durable response replay. Existing database checks and constraints remain authoritative. Completed instant verification and an existing initiated claim remain no-ops through unchanged service behavior.
- The default two-minute lease does not mean requests wait two minutes. Normal release is immediate; acquisition retries default to a two-second budget, plus Redis transport latency. Both values are configurable independently. A crashed worker or failed release may leave the key until expiry; no buffer is added to the configured lease.
- No request execution timeout is configured in this API and ASP.NET Core has no general default. Proxy timeouts do not forcibly stop action execution, so the operational lease must cover actual ongoing work, not merely the time a proxy waits for a response. Do not describe either setting as an HTTP request timeout.
- Leases are not renewed. Work running beyond the lease, Redis failover, and writers entering unannotated actions can still race. Keep constraints; do not describe this as exactly-once protection.
- The new helper uses a unique owner value and owner-checked release. The old background-job/payout lock methods retain their existing behavior and are outside this hotfix slice.
- The tests cover real Redis-compatible transport/leases and constrained SQL transactions, with mocked business/provider boundaries as documented above. They do not establish Redis failover, a hard process kill, or full instant-verification/referral-claim reward/notification behavior.
- No API header/body-shape changes. A contender still busy after the budget gets RequestInProgressException/409 with the existing error-list body. Redis acquisition errors remain errors and do not fail open. Domain success/no-op/validation logic is untouched; contention timing is intentionally different.
