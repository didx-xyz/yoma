## What Was Done

- Made `offline_access` an optional client scope on every client in `01-yoma-realm.yaml` and in the realm defaults for new clients. Raised the SSO session timeouts to 30 days idle and 60 days maximum. Details in [feature.md](../feature.md).
- Reproduced the bug and checked the fix on a throwaway `quay.io/keycloak/keycloak:26.4.0` container, with two confidential clients (`web` and `partner`) and a password login followed by a code exchange on `web`:

  | `offline_access` on clients | `web` refresh token | Silent `prompt=none` on `partner` | Explicit `offline_access` on `partner` |
  |---|---|---|---|
  | default (today) | `Offline` | `login_required` | `login_required` |
  | optional (this change) | `Refresh` | code issued | `Offline` token issued |

  The `web` refresh grant returned 200 in both cases.

## Gotchas

- Web users who are signed in at rollout hold offline refresh tokens. Those tokens keep working until they expire, and new logins get session-bound tokens.
- A web user's refresh token now dies with the browser session. Signing out of Keycloak or reaching the session maximum signs them out of Yoma too.
- Swagger still requests `offline_access` explicitly (`appsettings.json`), so a Swagger login still ends that browser session.
