## Recovery gate

Deployment corrects future evaluations, not every existing claim automatically. Re-evaluate eligible Pending claims using `ILinkUsageService.ProcessProgressByUserId`, preserving its user lock, transactional state recheck, eligibility, treasury/counter updates, reward scheduling and notifications. Do not set Completed directly in SQL.

`ILinkUsageBackgroundService` only exposes expiry/abandonment jobs. `LinkMaintenanceService.ProcessUsageProgressByProgramId` runs on programme requirement reductions, but repeatedly selects the first Pending batch. An incomplete claim can make it repeat indefinitely. Do not toggle programme requirements or use this helper as a recovery shortcut. A separately reviewed bounded trigger remains necessary, with fresh per-user service scopes and a finite approved worklist. No trigger added to this hotfix.

The processor expires overdue Pending claims before evaluating completion. Re-audit status/deadline immediately before recovery. Claims since expired belong to separate historical repair; do not infer historical entitlement from current rules or extend windows as a workaround.
