## How features must be tested (the foundation rules)

1. **One spec file per feature area, one test per user-visible behaviour, journeys not clicks.**
   A test is a short journey (navigate → act → assert outcome + server truth when cheap, e.g.
   `/api/auth/session`). Don't split one journey into five one-assert tests: each test pays a
   fresh context + page load. Don't merge unrelated journeys either: a failure must name the
   behaviour.
2. **Independent and parallel-safe by default.** No test depends on another's side effects.
   Mutating tests use data they create themselves (throw-away) or data the seed guarantees and
   they don't change. Only when state genuinely chains (phone register → login → reset) use
   `test.describe.configure({ mode: "serial" })` inside that file — never across files.
3. **Sessions come from the project, never from the test.** Put the spec under the role folder;
   `storageState` is loaded for you. Logging in inside a spec costs ~12 s and is only allowed in
   `public/` tests that are *about* logging in.
4. **Seed is the contract.** Assert only on `e2e/seed.ts`. Need fixed data? Add it to `post.sql`
   and `seed.ts` in the same change with a NOTE for Adrian.
5. **Locators: `#id` first.** Add a unique `id` + `// e2e` comment to the component if missing
   (required-prop pattern for shared components). Role/text locators only for text the user
   reads. No `data-testid`.
6. **Tag the one cheapest journey per area `@smoke`.** The PR gate runs `test:e2e:smoke`
   (minutes); the full suite runs on merge/nightly. Everything else untagged.
7. **Waits.** Prefer `expect(locator).toBeVisible()` over `waitForLoadState("load")`; use
   `goto(url, { waitUntil: "commit" })` on pages with heavy embeds. No `waitForTimeout`.
8. **Run before handing back**: `pnpm lint` and `pnpm test:e2e --project=<role>`; paste the
   result in the handoff; tick the sitemap row with the spec name.
