## What Was Done

- Stage Replay exposed two domain issues: cleanup failures bypassed the common retry counter/limit, and remaining Replay rows blocked every Pending issuance. Re-running did retry cleanup; it was not a stuck job lock.
- The worker now sends all failures to the existing Error handling in `SSICredentialService.UpdateScheduleIssuance`. That method reads the persisted status/count, increments using the existing convention and applies `SSIMaximumRetryAttempts`. Cleanup retries return to Replay; ordinary issuance retries return to Pending. Exhausted retries remain Error.
- Cleanup failures retain credential identity, schema version and original issuance date. Identity/date checkpoints do not consume retries. Successful cleanup clears retry/error state before ordinary issuance.
- Removed the global Replay-exists gate and its unused service method. Cleanup batches still run first; failed items are skipped for the rest of that run, while successfully cleaned and unrelated Pending rows can issue.
- Tests cover mixed cleanup success/failure across multiple batches at parallelism 1 and 3, one attempt per failed item per run, authentication failures before checkpointing, zero/finite/unlimited retry settings, terminal Error exclusion, failed cleanup persistence and ordinary issuance retry behavior after cleanup.
- After Stage reconciliation, Adrian requested the deferred schema PATCH fix in the same branch. The existing schema-write helper now reads the provider's latest definition under its distributed lock and compares the complete ordinal attribute set and artifact type. Identical definitions reuse the current version without provider upsert/cache invalidation; changed definitions retain the existing versioning/invalidation behavior. No provider-specific workaround or force flag. Swagger documents HTTP 200 with the existing version for unchanged updates.
- Schema regressions cover SDJWT and existing ACR/JWS defaults, reordered public/custom fields and implicit system fields, real additions/removals, historical reads, concurrent identical updates, cross-service cache invalidation and partial provider-write failures. Existing validation and Create checks remain in place.
- Review correction: removed the duplicate public-attribute comparison from background seeding. Existing schemas now pass through the same Update flow as admin PATCH; the private `UpsertSchema` method owns complete attribute-set comparison under the write lock. Trimmed, ordinal comparison retains the seed convention while also including domain internal attributes. Re-ran the full SSI suite successfully after this consolidation.

## Gotchas

- First failure is count 0; subsequent failures are retries. The existing limit comparison is unchanged, including zero disabling retries and -1 allowing unlimited retries.
- An exhausted cleanup in Error is not confirmation of deletion. If an operator later retries it, deliberately restore Replay, not Pending, retaining its credential identifiers/version/date and resetting the retry count as appropriate.
- This change does not bypass identity verification or automatically repair missing accounts. It does not change issuance eligibility or implement YoID revocation.
- Unchanged PATCH no longer forces a new preset version. The one-off Stage refresh already completed before this change; do not reuse that procedure as a force-version mechanism.
