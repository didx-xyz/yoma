## What Was Done

The API now rejects non-HTTP/HTTPS URLs on write; existing rows and partner responses still reach
the web unchecked. Every place the web navigates to a data-sourced URL was reviewed:

| Destination | Finding |
|---|---|
| "Go to opportunity" (`OpportunityPublicDetails.onProceedToOpportunity`): stored `url`, or the Pull partner's pre-auth URL from `performActionNavigateExternalLink` | **Fixed.** Assigned unvalidated to `win.location.href` of a blank tab opened from Yoma's origin (a `javascript:` value would run as Yoma), and that tab kept `window.opener`. |
| Cash out payment page (`lib/payout/handoff.ts`) | Already https-only (`isSafePaymentUrl`). |
| Organisation website, provider website/logo, news, marketplace reason links | JSX `href` — React 19 blocks `javascript:` URLs; provider links already go through `absoluteWebURL`. |
| Sign-out `callbackUrl`, referral cards | Resolved against Yoma's origin / built from Yoma routes. |

Fix: the destination goes through `absoluteWebURL` (`components/Opportunity/providerFacts.ts`,
http/https only, unit-tested incl. `javascript:`); on rejection the blank tab closes, the youth sees
"This opportunity's link can't be opened. Please let the organisation know." and
`opportunity_external_link_unsafe` is tracked. `win.opener = null` before any partner page loads;
the popup-blocked fallback opens with `noopener,noreferrer`.

Test: `e2e/youth/opportunity-handoff.spec.ts` — API-creates an opportunity with a partner URL
(`createOpportunity` gained an optional `url`), youth clicks Go to opportunity (and Proceed when the
leaving-Yoma notice shows), asserts the tab lands on the URL with `window.opener === null`. The
partner host is routed, never fetched. Fails on the pre-fix component (opener present), passes
after. The unsafe-link branch has no e2e: the details page loads server-side and the API no longer
accepts such a URL, so it cannot be planted; `absoluteWebURL`'s unit tests carry it.
