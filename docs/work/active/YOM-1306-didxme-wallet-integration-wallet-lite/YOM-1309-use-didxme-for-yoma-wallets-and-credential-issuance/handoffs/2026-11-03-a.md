## Gotchas

- Applying the migration runs the reset immediately; it is not an optional seed triggered later.
- Databases that already applied this migration will not pick up the appended seed. Disposable
  development databases can be fully reset; persistent environments need a reviewed follow-up
  migration if already applied. Do not edit migration history to force a rerun.
- Existing Replay rows become Pending because cutover must not delete old credentials through the
  new provider. This does not resolve normal background Replay or lost-issuance recovery.
- Retaining Aries storage does not make automatic fallback safe: domain provider IDs are reset.
- Null historical dates cannot be recovered exactly from the current schedule; the legacy fallback
  is an approximation. Obtain authoritative historical dates before cutover if required.
