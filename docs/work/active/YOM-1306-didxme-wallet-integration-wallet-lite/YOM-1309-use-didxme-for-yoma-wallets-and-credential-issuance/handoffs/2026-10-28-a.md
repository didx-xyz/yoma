## Gotchas

- Issuer tokens are not holder tokens. The implemented cache is singleton-instance scoped to one options registration, with no static state; do not extend it into a shared user-token slot.
- Token expiry is counted from before the HTTP request and refreshed early. The service assumes stable `IOptions` for its lifetime; credential rotation/configuration changes currently require normal service restart. API-operation 401 invalidation/retry is future work.
- No unsupported holder/delete operation is hidden behind a stub or a successful return. The shared interface is the target; creating a fake full provider would obscure the remaining contract gaps.
- Current YoID scheduling uses ACR, opportunities default to JWS and scheduled rows retain their format. The adapter needs an explicit translation/transition design covering both; no domain format change was made in this step.
- Selective-disclosure rules, claim typing and preset identity/version mapping remain design work. Do not silently change current claim mappings or optional-value handling.
