## What Was Done

- Agreed that wallet display relies on provider issuance/receipt verification and current lifecycle checks. Removed the per-view cryptographic verification TODO and superseded the temporary-default plan. This does not replace presentation/proof verification when a credential is used.
- Added `Expired` to the shared credential lifecycle enum without changing existing numeric values. The didx:me adapter reads optional `exp` from the wallet response and compares it with UTC now. It does not infer expiry from an arbitrary public attribute or issue date.
- Confirmed revocation takes precedence over expiry. Known expiry remains Expired if issuer status is unavailable or correlation is missing; otherwise those cases remain Unknown. List/detail retain expired and revoked wallet copies.
- Detail maps Issued to Verified, Revoked/Expired to Invalid and Unknown to Unknown. The separate verification field remains absent from list items.
- Updated [Jason's canonical UI handover](./2026-11-11-c.md#jason--wallet-status-tags), the feature checklist and the epic contract. Show Expired on cards and Invalid with the expiry reason on detail. No UI code was changed.

## Gotchas

- Verified is a wallet display result, not evidence of a fresh cryptographic verification or authorization to accept a proof. No verification timestamp is claimed.
- Expiry depends on the provider returning the signed expiry. An absent expiry does not schedule any automatic expiration, cleanup or replacement.
- Tests use HTTP-backed provider fixtures. This follow-up did not repeat live wallet tests or perform a cryptographic proof verification.
