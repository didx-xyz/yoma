## What Was Done

- Removed the additional signed tracking attribute from newly created presets and issuance. The existing client referent remains; it identifies the domain issuance schedule, not the participant.
- Issuance persists the offer identifiers before delivery, then waits inline for durable webhook acceptance. The domain receives the native holder-wallet ID.
- Added authenticated webhook correlation with duplicate/conflicting-event checks. Database persistence completes before acknowledgement. Both standard and vendor-prefixed signature headers are accepted.
- Added background reference lookup and confirmed deletion for Replay. Failed reads never mean absence; ambiguous delivery never triggers blind reissuance. Pending/rejected matches and duplicate references require reconciliation.
- Consolidated holder context, reading and recovery into one holder service. Services/clients use interfaces; repositories retain mapping/persistence only. Tracking coordinates local writes through the existing execution-strategy and row-lock patterns.
- Applied Adrian's review: string database status with infra enums for decisions; no EF enum conversion, aliases, arbitrary webhook size limit, interface cache keys or default entity status. Configuration stays with its owning adapter. No separate Keycloak options-validation helper.

- Resolved the reported analyzer suggestions: cancellation token last in wallet paging, reusable constant arrays, collection expressions and a static wallet-response test helper. No migration operations or application behavior changed. Rebuilt cleanly and reran the didx:me suite: 125 passed; the explicit live proof was not rerun for this cleanup.
- Preserved the webhook secret through local configuration merging. No credentials or private platform setup instructions are included here.
- Final review corrected recovery after a schema-version advance: return the original issued version of the same schema, allowing the unchanged domain to retain its actual version/date. A different schema remains rejected. Four regression cases cover both outcomes with/without a local journal. Corrected a live-test comment: that test exercises reference lookup, not loss of the journal; missing-journal recovery has unit coverage.

## Gotchas

- No distributed transaction makes remote issuance and Yoma persistence atomic. A delivery attempt with no visible wallet result stays blocked for reconciliation; absence alone is not permission to deliver again.
- Native IDs change persistence semantics. Never feed an old adapter row ID into the new wallet API path.
- Keep old presets available for resolving existing wallet credentials during Stage cleanup.
- This handoff supersedes the previous description of identity-interface cache/deadline properties: those properties were removed during review.
