### 9 November API follow-up — ordinary edits preserve the pool

- `OrganizationRequestUpdate` no longer includes `zltoRewardPoolCurrentFinancialYear`. Older full-update payloads that still send it cannot change the pool; clients must use the dedicated endpoint for a pool change to take effect.
- Creation still accepts the initial pool with the existing Admin-only permission and value limits. The dedicated endpoint retains its permissions, limits, allocated-total check and null-clearing behavior.
- `OrganizationService.Update` reads the current pool using `LockMode.Wait` inside its existing transaction, then copies it onto the model immediately before the repository update. This prevents a stale ordinary edit from overwriting a concurrent pool change. Repository interfaces and persistence remain unchanged.
- This supersedes earlier handoff wording allowing pool edits through a full organisation update. No schema migration or API response-shape change is needed. Jason must coordinate the UI adoption before release.
