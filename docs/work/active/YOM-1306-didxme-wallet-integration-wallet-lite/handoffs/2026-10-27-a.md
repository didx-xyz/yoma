## Gotchas

- didx:me has **no org-token read or delete** on wallets: `/v2/orgs/*` is write-only. Every
  `ListCredentials` / `GetCredentialById` / `DeleteCredential` needs a user-scoped token, i.e. a
  Yoma user access token to exchange. `SSIBackgroundService` Replay runs without one. See plan § 5 #1.
- Presets are **write-once** (409 on duplicate `type`). Yoma's "same name → new version" schema
  semantics must be encoded in the preset `code`.
- Credentials are SD-JWT VC, not AnonCreds. `ArtifactType.ACR` requests must be rejected by the
  adapter, and `claims{}` come back nested-capable; keep Yoma presets flat.
- The JWT-grant assertion must have `sub` == the `externalIdentifier` stored at onboarding. If
  we onboard with anything other than the Yoma KC `sub`, the exchange silently fails. Hence
  holder tenant id = `User.ExternalId`.
- `POST /v1/presets/credentials` returns **200**, not 201; `POST /v2/orgs/credentials` returns
  `{data:null}` — do not expect a credential id from the push, read it back via the user token.
- Local didx:me Keycloak fetches Yoma's JWKS from inside the kind cluster; Yoma's compose Keycloak
  (`http://keycloak:8080`) is not reachable from there without extra wiring.
- WSL2 without sudo: the mono Tilt setup shells out to `python3`/`unzip`/`rsync`/`envsubst`;
  `~/.local/bin` shims were enough. A CRLF checkout breaks every mise task.
