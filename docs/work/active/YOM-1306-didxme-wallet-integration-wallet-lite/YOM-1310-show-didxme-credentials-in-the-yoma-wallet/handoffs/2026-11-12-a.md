## What Was Done

- `src/web/src/api/models/credential.ts`: `CredentialStatus` and `CredentialVerificationStatus`
  enums; `status?` / `verificationStatus?` on `SSICredentialBase` (optional because a pre-#2028
  API omits them; both wire values are enum names).
- `src/web/src/lib/credentials/credentialStatus.ts`: the single verdict mapping for card and
  detail — `credentialBadge()` returns `verified | invalid | unverified` with a label and a
  reasoned description ("Invalid — revoked" / "Invalid — expired"). Verified needs both
  `Verified` and `Issued`; Invalid wins on `Invalid`, `Revoked` or `Expired`; everything else
  (Unknown, missing, contradictory) is Unverified.
- `src/web/src/components/Credentials/CredentialStatusBadge.tsx`: the pill (`data-status` =
  verdict, `title` = description). `CredentialCard.tsx` uses it in place of the hardcoded
  "Verified" and now carries `data-credential-id` on the `<article>`. The passport detail dialog
  gets a "Status" row (`#credential-detail-status`) with the full wording.
- `src/web/e2e/youth/passport-status.spec.ts` (4 tests, 1 `@smoke`): stubs wallet search and
  detail on the browser context with all four lifecycle values, a legacy response without the
  fields, a contradictory `Revoked + Verified` pair, and the revoked + issued YoID pair; asserts
  card tags, detail parity, no dedupe and the header count. Page, auth and type lookup are real.
- Docs: `feature.md` (status in-progress, decisions), epic README child row, `known-gaps.md`
  row for the live-provider check this spec cannot make.

## Gotchas

- Playwright evaluates context routes most-recent-first; a detail route matching
  `/ssi/wallet/user/[^/]+` also captures `/search`. The spec's detail regex excludes `search`.
- The verdict is a wallet display result, not a proof check (API contract). Nothing in the UI
  may branch an action on `verified`.
- `OPP_CONTRADICTORY` in the spec is a guard, not a real API state — Adrian's mapping never emits
  `Verified` with a non-`Issued` lifecycle.
