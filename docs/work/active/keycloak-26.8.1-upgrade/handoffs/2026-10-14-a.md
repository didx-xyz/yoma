## What Was Done

- Read the upgrading guide entries from 26.4.1 to 26.8.1 and checked each one against our realm, providers, theme and Helm values. The ones that affect us are in `feature.md`.
- Bumped the Keycloak image to 26.8.1 and keycloak-config-cli to `6.5.1-26.5.5`. Rebuilt the provider JARs against 26.8.1.
- Fixed the two realm import failures on 26.8.1 (`realm-management` 403, duplicate delegation scope on fresh import). Kept the password fields on the registration form.
- Ran the local compose stack under a separate project name (`docker compose -p kcupgrade`):
  - Ran a 26.4.0 baseline with the old files. The import passed and I created a test user with a password.
  - Swapped in the new images, JARs and export on the same database. Keycloak migrated the model (26.4.3, 26.6.x, ... 26.8.x) and logged no errors. keycloak-config-cli imported all three files.
  - Registered with email and password through the phone theme. The verification mail arrived in Mailpit and the link verified the email. The password was stored at registration.
  - The pre-upgrade user logged in through "Browser with phone".
  - The webhook listener fired on events. Delivery failed because the API was not running.
  - Ran a fresh install on an empty database with the final files. The import passed and Keycloak logged no errors.
