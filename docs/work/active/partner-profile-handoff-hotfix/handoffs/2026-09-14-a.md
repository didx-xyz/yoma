## What Was Done

- Investigated production Alison registration failure caused by a missing first name.
- Initial account creation legitimately permits incomplete onboarding data. The defect is allowing a required partner hand-off without the necessary profile fields.
- Added partner-specific profile validation in `src/api/src/domain/Yoma.Core.Domain/PartnerSync/Services/SyncUserAuthenticationService.cs`, before provider construction or authentication.
- Alison: email-based registration (no existing partner link) requires first name, surname and a resolvable country. Already-linked login retains its email-only contract.
- IXO: email-based hand-off requires first name, surname and a resolvable country, even for an existing link.
- Empty/whitespace email retains the existing provider-owned mobile-only redirect behaviour. Partners without user-authentication capability and unrelated partner contracts are unchanged.
- FluentValidation exceptions now propagate instead of being swallowed by the best-effort URL fallback. Other provider failures retain the existing fallback.
- Added isolated mocked service regression tests; no live partner requests or database writes are performed by those tests.
- Added derived `SyncInfoUserPartner.IsLinked`, excluded from Newtonsoft.Json serialization using the existing serializer convention. Both Alison flow selection and the new validation use it; it has no independently stored state and does not prove an account exists or does not exist at the partner.

## API / UI Contract

- Endpoint: `PUT /api/v3/myOpportunity/action/{opportunityId}/navigateExternalLink`.
- Existing exception middleware returns HTTP 400 with an array of `{ type: "ValidationException", message: "..." }` objects, one per missing field.
- Example message: `Please complete your Yoma profile: first name is required to continue to Alison.`
- ValidationFailure property names are FirstName, Surname and Country internally; the current public error response exposes messages, not property names. No new response schema or dependency was added.
- Jason must not swallow this 400 and redirect to the raw opportunity URL. Prompt profile completion and retry after a successful profile refresh.
- API partner validation is NOT a replacement for general Yoma onboarding (including gender/DOB), which remains a UI requirement.
