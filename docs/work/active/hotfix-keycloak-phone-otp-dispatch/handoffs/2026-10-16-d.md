2. Write `/tmp/kc-twilio.yml` **outside the repo**, with `services.keycloak.environment` set to:

   Get Stage's Twilio values from Robbie or the Stage secrets. Never commit them.

3. `cd src/api && docker compose -f docker-compose.yml -f /tmp/kc-twilio.yml up -d keycloak`. This keeps the JARs in the volume. Then sign up through the local web app, or call `http://localhost:8080/realms/yoma/sms/registration-code?phoneNumber=…`.
4. Afterwards, recreate `keycloak` without the override (`docker compose up -d keycloak`) to go back to the dummy sender.

This sends real, billable messages, so use your own and colleagues' phones and keep the count low.

## Gotchas

- Stage needs a push: Helm can't see an uncommitted or unpushed branch. Option A avoids that.
- All four changed JARs must deploy together. A pod with mixed versions can fail with `AbstractMethodError` because the sender SPI return type changed.
- Each failed send now uses one of a number's 3 attempts per hour. During testing, expect 403s sooner than before.
- To reset Stage limits for a test number: delete its rows from `phone_message_token_code`.
- The harness from the c handoff is in `/tmp/otpharness/`. It won't survive a WSL restart.
