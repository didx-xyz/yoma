What it shows:

- **The new code is live.** The one send after the release wrote `also sending SMS`, a line only the new sender writes. That was a ZA number whose WhatsApp wasn't confirmed in time, so it got the SMS backup and its code was saved. No old-sender lines after the release.
- **Before the release:** 30 requests = 12 saved + 4 failed (503) + 14 refused because a code was still valid. All 4 503s were non-ZA numbers refused SMS. 3 of them were the incident: WhatsApp stuck at `sent`, so no code was saved. The fix saves those codes and shows the amber warning instead.
- **14 of 30 requests were refused as already sent.** That fits users clicking "Send OTP" again while waiting, which #1986 fixes. Watch this number fall.
- **Too early to conclude.** Traffic is about 30 sends a day and the incident only a few times a day. 1 request after the release proves the code is live, not that the 503s are gone.

## How to Run the Log Review

From the repo root, with `DD_API_KEY` and `DD_APP_KEY` set using `export NAME='…'` in the same terminal (not `set`, which only sets positional parameters). The application key must be allowed to read logs (`logs_read_data`). A key scoped to `rum_read` only, like the one `src/keycloak/scripts/datadog-example.ps1` was written for, gets 403 on the logs APIs. `DD_APP_ID` is not needed by these APIs and is ignored. The site defaults to `datadoghq.eu`.

1. `mise x -- node src/keycloak/scripts/otp-dispatch-report.mjs --discover`. The default scope is `service:keycloak env:v3-prod`, because Production's env tag is `v3-prod` for `yoma-web` (`datadog-example.ps1`). Keycloak's Helm values don't set the tag themselves, so confirm it's listed. Otherwise use the Production `kube_namespace` or `kube_cluster_name` value as the scope.
2. `mise x -- node src/keycloak/scripts/otp-dispatch-report.mjs` (add `--scope "…"` if step 1 showed a different tag). The defaults compare the 24 h before `2026-10-19T08:28:34Z` with the time since. Change them with `--release`, `--before-hours` and `--to`. `--dry-run` prints the queries without calling Datadog.

What good looks like:

- **503 rate falls.** Before the release, most 503s were non-ZA numbers stuck at `sent` (`Old: no receipt in window` together with `Non-ZA number refused SMS`).
- **`Non-ZA: sent, delivery unconfirmed (the fix)` is above zero.** These users now get a working code and the amber warning instead of a 503. This is the first real check of the non-ZA path.
- **`Failed send not counted` and `Crash signatures` stay at 0.** The crash search only covers the log message. If Datadog keeps stack traces in a separate attribute, also check the Keycloak error logs directly.
- **No `Old:` lines after the release.** If they appear, a replica is still on the old JARs or `--release` is too early. Rollout finished some time after the release was published.
- **Twilio codes.** Codes other than 21211, 21614, 63003 and 63024 return 503. Any frequent one is a candidate for the 400 list, or points to an account or template problem.
