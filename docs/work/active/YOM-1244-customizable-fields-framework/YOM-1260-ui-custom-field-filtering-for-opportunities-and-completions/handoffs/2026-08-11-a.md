## What Was Done

Audit and completion of **T4 — custom-field search filters (YOM-1260)**, plus the
refactor that made the same UI usable by the admin search.

### The reported crash

`Objects are not valid as a React child (found: object with keys {key, operator, value, valueTo, values})`
on the public opportunity search. `FilterBadges`' `resolveValue` fell through to
`return value`, handing a whole `CustomFieldFilter` clause to React. Fixed with a
`customFields` branch that renders the clause's value(s) via `useCustomFieldFilterLabeler`.

A second, related defect surfaced immediately after: `Encountered two children with the same key,
searchFilter_filter_badge_customFields_[object Object]`. The badge key interpolated the raw
array item, so every object-valued clause stringified identically. `FilterBadges` now folds the
array index into the key and omits the item when it is an object — primitive filters' keys are
effectively unchanged.

### Defects in the pre-existing filter code, each verified against a running API

The first pass at T4 had been left inline in `OpportunityFilterVertical` and did not match the
API contract. Confirmed by `curl`ing `POST /api/v3/opportunity/search` before and after:

1. Option filters submitted the option **`id`** → `ValidationException: contains an invalid option value`.
   Now submits the option **`key`**.
2. Option + `Equals` submitted `values` → _"filter value does not match the selected operator"_.
   Now uses the scalar `value` (writes still use `values` for every Option field — the two paths differ).
3. `AllOf` was offered for single-select options → _"does not support multiple values"_. Now hidden
   unless `supportsMultiple === true`.
4. `GreaterThanOrEqual` / `LessThanOrEqual` / `AnyOf` were missing from the operator matrix.
5. Lookup-backed Country / Language / Skill definitions rendered as a free-text _"Enter option ID"_
   box. Now real pickers submitting lookup GUIDs (Skill async-searched, same pattern as the editor).
6. Single-select Option + `Equals` rendered a text box instead of a dropdown.
7. DateTime submitted a bare `yyyy-mm-dd`; now ISO-8601 via `dateInputToUTC`.
8. An inverted `Between` range reached the server and 400'd; now blocked client-side with an inline error.
9. The `customFields` query param was double-encoded (`encodeURIComponent` inside `URLSearchParams.append`).

### The refactor

- **New `components/Opportunity/CustomFieldFilters.tsx`** — the whole filter surface in one
  controlled, definition-driven component: operator matrix per data type, inline options by key,
  Country/Language/Skill pickers, DateTime conversion, `Between` with an inverted-range guard.
  Exports `sanitizeCustomFieldFilters` (drops half-completed clauses), `getCustomFieldFilterErrors`
  (blocks submit rather than letting the API reject), and `useCustomFieldFilterLabeler` (badge text).
- **Both vertical filters consume it** — `OpportunityFilterVertical` (≈200 lines of inline markup
  removed) and `OpportunityAdminFilterVertical` (new "Additional fields" accordion, react-select
  portalled to the modal's `htmlRef`).
- **`getCustomFieldNumberError` exported from `CustomFields.tsx`** so the filter and the editor
  apply one numeric rule set (Int32 range, invariant decimal, `decimal.MaxValue`).
- **Control sizing** — react-select's control keeps a 38px min-height that its `classNames` API
  cannot override, so the native selects/inputs were moved off `select-sm` / `input-sm` onto
  `h-10 min-h-10 py-1 text-sm` to match it. Both react-select controls (Select and the Skill Async,
  which previously differed from each other) now share one class constant.
- **Disable switch** — a commented-out `CUSTOM_FIELD_FILTERS_ENABLED = false` with a
  `TODO(YOM-1260)` at the top of the component, per the decision to park the toggle rather than
  ship a live flag.

## Gotchas

- ⚠️ **`zodResolver` strips unknown keys.** Custom-field state cannot live in the form object;
  both vertical filters keep it in local state and merge it into the payload in `onSubmitHandler`.
  Any _other_ surface that submits a filter must carry `customFields` through, or changing an
  unrelated dropdown will silently drop every clause. The admin page is safe because
  `opportunityAdminFilter.ts` rebuilds the whole filter from the querystring; a form-derived
  submit path would need an explicit `customFields: zod.any().optional().nullable()` passthrough.
- ⚠️ **Reads and writes disagree on Option shape.** Writes use `values` for every Option field;
  the _filter_ uses `values` only for `AnyOf` / `AllOf` and the scalar `value` for `Equals`.
- ⚠️ **Opportunity saves are replacement, not patch.** Always resubmit the full collection —
  omitted keys are deleted server-side.
- **Skill labels fall back to the GUID until searched.** There is no batch get-by-ids for skills,
  so a Skill value that has not been through the async search shows its GUID in read-only views.
  Pre-existing limitation, also affects `CustomFieldsView`.
- **`types` on the definitions endpoint is the enum name, not the type GUID.** Passing the GUID
  silently returns only the generic definitions.
- The seeded definitions are all prefixed `[Sample]` and are **not** BA-approved. Do not treat
  their keys, titles or option sets as stable, and do not write anything that references them.
