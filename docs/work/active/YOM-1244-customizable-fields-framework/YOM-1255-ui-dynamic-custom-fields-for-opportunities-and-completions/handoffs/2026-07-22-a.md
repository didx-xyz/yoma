## What Was Done

**T1 — opportunity create / edit, and T3 — details.**

- **Foundation.** `CustomFieldDefinition`, `CustomFieldOption`, `CustomFieldValueRequest`,
  `CustomFieldValueItem` and the `CustomFieldDataType` / `CustomFieldLookupType` enums added to
  `api/models/opportunity.ts`; `customFields?` added to `OpportunityRequestBase`, `Opportunity`
  and `OpportunityInfo`. Definition services (`by types`, `by id`) plus
  `useOpportunityCustomFieldDefinitionsQuery(typeNames)`, keyed on the type name so it refetches
  when the wizard's type changes.
- **`CustomFields.tsx`** — the editable, definition-driven surface: one control per `DataType`;
  Option fields resolve to inline options, Country/Language selects, or an async Skill search;
  `supportsMultiple` picks single vs multi. Controlled, with a 400ms debounced `onChange`, a blur
  flush, and an echo-ignoring seed effect (an earlier version looped: emit → parent state → new
  `values` prop → re-seed → emit).
- **Validation extracted and exported** — `getCustomFieldError` / `getCustomFieldErrors`, pure, so
  the inline errors and step 2's zod `superRefine` share one rule set. Decimal magnitude is
  compared as digit strings because `decimal.MaxValue` exceeds JS `Number` precision.
- **Wizard integration** — bound through `<Controller name="customFields">` so the fields gate
  "Next" and the tab jump, and register in the unsaved-changes dialog. Submit reconciles to the
  current type's definitions, drops empties and resubmits the **full** collection.
- **Read-only display** — `CustomFieldsView.tsx` plus `OpportunityCustomFieldsSection.tsx` on both
  the org-admin `…/info` page and the public opportunity details page. `DetailSection.tsx`
  extracted for the shared sidebar chrome; `FormField` / `FormLabel` gained an optional `badge`;
  sidebar icons standardised on `react-icons/io5`.

### Contract corrections found while building

The planning notes were wrong on three points, each confirmed against the API branch:

1. `lookupType` **does** exist on the definition (`Country` / `Language` / `Skill`).
2. `defaultValue` was **removed** — there is no default-value capability.
3. Entity responses **do** hydrate `customFields` (`OpportunityInfoService.GetById` →
   `includeChildItems` → `ToOpportunityInfo`).

## Gotchas

- ⚠️ **Saves are replacement, not patch** — omitted keys are deleted server-side.
- ⚠️ **`zodResolver` strips unknown keys**, so custom-field state cannot live in the form object.
- **Skill labels fall back to the GUID until searched** — no batch get-by-ids exists.
- The `types` query parameter takes the **enum name**, not the type GUID.
