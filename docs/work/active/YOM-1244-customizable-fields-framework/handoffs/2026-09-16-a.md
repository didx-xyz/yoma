## What Was Done

The branch is being prepared for a release **without** the custom-fields framework, so cash-out can
ship while the framework waits on its blockers. One hard-coded constant now switches the whole
thing off.

**The discovery redesign must not go live either** and is switched off by the same flag — see
`/opportunities/discover` below.

`CUSTOM_FIELDS_ENABLED` in `src/web/src/lib/constants.ts`, currently **`false`**. It follows the
`OPPORTUNITY_SEARCH_DESIGN_V2` kill-switch already in that file. Setting it back to `true` restores
everything; nothing else needs changing.

It is wired at **chokepoints, not at every call site** — the framework is definition-driven, so
starving it of definitions collapses the UI everywhere on its own:

| Gate                                          | Reach                                                                     |
| --------------------------------------------- | ------------------------------------------------------------------------- |
| `useOpportunityCustomFieldDefinitionsQuery`   | every opportunity CF surface — editors, read-only sections, filter panels |
| `useMyOpportunityCustomFieldDefinitionsQuery` | every completion CF surface                                               |
| `useTypeDefinitions` (discovery)              | the type-specific filter block                                            |
| `SCHEMA_ADMIN_MOCK_ENABLED`                   | schema mock banner, the Credential step's notice, all schema fixtures     |
| `USER_PREFERENCES_MOCK_ENABLED`               | the discovery `PreferencesMockDevTool` and all preset fixtures            |
| `CUSTOM_FIELD_FILTERS_ENABLED`                | CF filtering on all four search surfaces                                  |

Both definition queries are disabled at source, so nothing is fetched and every dependent block
renders nothing — `CustomFields`, `CustomFieldsView` and `CustomFieldFilters` all already returned
null on an empty definition set.

Four gates are not reachable from a chokepoint and were set individually:

- the completion form's CF panel — the grey card is the _wrapper_, so the empty state alone would
  render an empty box on every completion;
- the schema admin Opportunity Type context selector, its list column, and custom fields in the
  attribute picker. Existing _mapped_ attributes are deliberately untouched — they are read back
  from the schema itself, and hiding one would silently drop it on the next save.

**`/opportunities/discover` is switched off wholesale**, not just stripped of its CF parts: it is
the preset-driven prototype, and its preferences are mocked with no API behind them. The page's
`getStaticProps` returns `notFound`, and the user menu's "My preferences" entry — the only link
into it from outside the feature — is hidden by the same flag, so the route is unreachable rather
than merely empty. `getStaticProps` rather than `getServerSideProps` keeps the route statically
optimized when the flag is on; the flag is build-time, so whether the page exists is known then.
The old `/opportunities` search page is untouched and stays the discovery surface for this release.

`CUSTOM_FIELD_FILTERS_ENABLED` was a hand-edited boolean carrying a `TODO(YOM-1260)` asking for
exactly this gate; it now derives from the flag.

## Gotchas

- **Do not use a conditional spread at module scope with this flag.** Writing
  `params: [..., ...(CUSTOM_FIELDS_ENABLED ? [x] : []), ...]` in `opportunityAdminFilter.ts`
  compiled fine but **failed the production build** — webpack emitted the flag as a bare
  identifier, so page-data collection died with a `ReferenceError` naming it as undefined. It was
  the only such emission in the entire server bundle; every other usage inlined correctly. That
  gate was dropped as unnecessary, but the hazard applies to any future one.
- **The flag cannot protect stored custom-field values.** Both save paths reconcile submitted
  values against the _loaded_ definitions, so with none loaded they submit an empty collection —
  and the API's upsert is replacement-mode (`CustomFieldUpsertMode`), which deletes values for
  omitted fields. Sending `null` instead makes no difference: `ValidateAndNormalize` does
  `customFields ?? []`. **On an environment that still has definitions and values seeded, editing
  an opportunity or completion through the web will wipe them.** Production is safe because
  seeding was disabled in `c955ce77`; DEV/STAGE may not be. If a required definition exists, the
  save will fail validation outright instead.
- The flag is a build-time constant, so it is inlined and dead-code-eliminated. `false` leaves no
  CF fetch in the bundle, but it also means **flipping it needs a rebuild**, not an env change.
- Schema admin pages and the opportunity wizard's Credential step predate this epic on `master`
  and stay live — the flag strips only the CF parts. `/admin/schemas` has no nav link; it is
  reachable by URL only, as before.
- The youth passport credential display (YOM-1283) is deliberately not gated. It renders whatever
  attributes a credential carries and works fine for generic ones.
