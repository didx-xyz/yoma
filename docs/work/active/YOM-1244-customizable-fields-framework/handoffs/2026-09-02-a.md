## What Was Done

(the revision-pass baseline). Everything below is in ONE commit with this handoff.

### The one architectural change — provenance-aware controls

Display surfaces read `state.filters` (manual only) while the search ran on `effectiveFilters`
(manual + inherited preferences), so on landing nothing looked selected. Now **all controls
display effective values** and editing is provenance-aware, with ONE semantic everywhere:

- deselecting a **manual** value removes it; selecting adds manually;
- deselecting an **inherited** value **skips its owning preference** for this search (found via
  the fragment that supplied it) — identical to removing its chip. Granularity is per-preference,
  not per-value: deselecting one of two inherited interests switches off the whole Interests
  preference. A per-value override would need a `prefsSkip` URL-format change — flagged, not built.

Implemented in `useSectionModel` (all section bindings incl. commitment), `SegmentedSearchBar`
summaries, and `CategoryCarousel`. `AppliedChips` now also renders on the **landing** page
(departure from the design's "no chips on landing" — the inherited layer must be visible and
editable before a search runs).

Related: the static `FROM PROFILE` badge became a truthful **FROM PREFERENCES** badge — shown only
while a section actually receives an active inherited value (fragment present, master switch on,
not skipped); the registry's dead `fromProfile` flag was removed; the binding→facet map lives once
in `registry/filterSections.ts` (`FACET_FOR_BINDING`).

### Personalization dialog

- **Mount-on-open contract** (bug fix): the dialog seeds its edit draft from stored preferences in
  a `useState` initializer, so it must be mounted only while open —
  `{personalizeOpen && <PersonalizeDialog …>}`. Previously it mounted permanently, seeded while
  the query was still loading, and always edited an empty form. Doc comment states the contract.
- Fixed height `md:h-[85vh]` (same rationale as the fixed 340px panel: no resizing between
  steps); only the step content scrolls — progress row, purple panel and action footer are fixed;
  scroll position resets per step; footer buttons match the filter dialog's size and sit in a
  ScrollableContainer so they never wrap at 390px.
- `StepBlock` single-select is keyed by **prefKey**, not block kind — `rows`/`pills` are purely
  visual (fixed a cross-wiring bug where any pills block edited `engagement`).
- **Empty-state invites**: both preference banners ("Tune your feed" on the page,
  "No preferences set" in the filter panel) render a personalize CTA when no preferences exist —
  previously a youth who X-closed the wizard had NO re-entry point (X marks
  `personalizationSeen` without saving). Block 3 also no longer vanishes from the panel.

### Filter surfaces

- Type-specific filters restyled to match the universal sections exactly (one header pattern,
  `FROM THIS TYPE` badge is the only distinction), collapsed by default unless clauses are set,
  and contiguous with the section list. Sections collapse by default unless they carry a selection;
  expanding any section (and "More filters") scrolls the revealed controls into view.
- Recents render as a truncating typeahead under the input; section null rules, wizard notes,
  the type-row hint, pending-API notes and the list-view explainer all use the new shared
  `<Message>` (info/warning/error, icon + tinted panel).
- FiltersDialog title carries a round **green** count badge (`chips.length`); full-screen below
  `md`, centred dialog above. Native `<dialog open>` elements replace `role="dialog"` divs
  (Sonar S6819) in all three overlays.
- Body scroll locks while any dialog/sheet is open; segment popovers anchor under their own
  segment and close on outside click; the desktop bar lost its dead search button and gained the
  Filters button (with count) inside the input; the mobile pill shows the same count.
- `FloatingFilterButton` (discovery version of the old page's `FilterTab`): purple pill with
  count, fades in past 300px scroll, both breakpoints.

### Shared components extended (additively — defaults keep existing callers pixel-identical)

- `ScrollableContainer` gained `shadowFromClassName` (edge fades must match the surface behind:
  `from-purple` in the hero, `from-gray-light` on the body — the default 5%-tint was invisible)
  and `containerClassName` (default `h-full` for the Navbar; the wizard footer passes `""`
  because `h-full` stretches inside definite-height flex parents). Used for quick-search rows,
  applied chips, count/sort/view row, category browser, wizard footer, preference chips.
- daisyUI 5 toggles coloured the native way — `checked:[--input-color:var(--color-purple)]`
  (what `toggle-primary` does); the previous `checked:bg-purple` fought the system and produced
  the black-dot-on-purple.
- **App-wide**: `globals.css` base rule restores `cursor: pointer` on enabled buttons (Tailwind
  v4 preflight sets `default`; daisyUI restores it only for `.btn`). Affects the whole app.
- `AnimatedText` interval 3s → 6s (Jason) — also affects its old-page caller. Now used in the
  hero with context-aware sentences (landing vs results), rendered on both so no layout shift.
