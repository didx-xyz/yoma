### 1. Saved skills no longer render as GUIDs (YOM-1261)

`UserPreferences.selfReportedSkills` changed from `string[]` (EMSI ids) to
`UserPreferenceSkill { id, name }[]` — the EMSI lookup is search-by-name only, so a bare id could
never be resolved back to a label when re-editing. Ripples, all small because skills feed no
filter yet (`binding: null`): `SkillSearch.tsx` simplified (its per-mount label cache is gone —
the stored pair IS the label), and both store read paths (`userPreferencesLive`, the mock) now run
`normalizeUserPreferences`, which **drops legacy bare-id entries** (mock-era data; unresolvable
GUID chips are worse than a clean slate). When YOM-1257 lands, the preset model should store the
pair or return labels — added to the asks for Adrian.

### 2. Anonymous → signed-in migration (YOM-1261)

- `state/useAnonymousMigration.ts`: when scope is `user` and session-held anonymous answers exist
  (read through the façade with scope `"anonymous"` — the façade rule holds), exposes a tri-state
  `pendingAnonymous` (`undefined` checking / object offer / `null` none) plus
  `keepAnswers`/`discardAnswers`.
- `shared/KeepAnswersPrompt.tsx` renders the one-time offer at the top of `<main>` on both landing
  and results. Keep = `mergeUserPreferences(stored, anonymous)` — unions multi-selects, session
  answers win where both set a single value, **never a silent overwrite** — saved through the
  façade; discard clears the session store. Both mark personalization seen (else the wizard
  auto-opens the instant the youth answers the offer).
- The wizard auto-open in `DiscoverySurface` now waits for `pendingAnonymous === null` — it must
  not race the async store read or fight the offer.
- Keep is disabled (component renders null) until the stored preset query resolves — merging into
  `EMPTY` while loading would clobber an existing preset.

### 3. Avatar-menu re-entry (YOM-1261)

param and strips it with a shallow `router.replace` — the param is an instruction, not state, so
it never lands in the recent-search/URL-codec world.

### 4. Design polish (from Jason's screenshots)

**Category cards stretched vertically** in the Browse-by-category carousel (both landing and
results — one shared `CategoryCarousel`). Root cause, verified with headless Chrome against the
running dev server: MainLayout's `<main class="flex min-h-screen …">` hands definite heights down
the flex chain; `ScrollableContainer`'s default `h-full` wrapper picks that up; the flex row's
default cross-axis **stretch** then inflates the card buttons, and because the shared card is
`aspect-square`, the stretched height transfers into WIDTH too — cards rendered 159×159 instead
of their natural 120×120. Fix (discovery-owned wrapper only, no shared-component change):
`items-start` on the scroller row + `containerClassName=""` — measured before/after in-page:
159×159 → 120×120, now pixel-matching the old page's `CustomSlider` rendering. Either change
alone breaks the chain; both applied as belt-and-braces.

## Gotchas

- **Why DEV `/opportunity/search` 500s while local works** (the session's question, answered
  empirically): the DEV database has this branch's migration
  `20260806191303_ApplicationDb_Custom_Fields_Treasury_Payout` applied (it DROPS
  `Entity.Organization.YomaRewardPoolCurrentFinancialYear`, `Opportunity.YomaReward`, …), but the
  pods behind `v3api.dev.yoma.world` are serving a **master-model image** that still maps those
  columns — every opportunity search selects them → `42703`. Proof: the branch-only
  `GET /opportunity/custom/field/definition?types=Job` returns **404** on DEV, while
  `dev.yoma.world/opportunities/discover` (web) is the branch build. Locally, binary and DB are
  both branch, so neither side references the dropped columns. Root cause: `yoma-v3-dev` is a
  shared last-deploy-wins environment (every PR against master deploys there;
  `helm/yoma-api/conf/dev/values.yaml` defaults `image.tag: "master"` unless CI's `TAG` is
  applied), and migrations only run forward. Any master-based deploy re-breaks it while the
  branch's destructive drops live in the DEV DB. Also recorded in the epic README's Cross-Area
  Notes.
- The keep-answers offer reads the anonymous store **through the façade** — do not import
  `userPreferencesLive` from feature code (the façade rule); scope `"anonymous"` reaches the same
  sessionStorage in both mock and live modes.
- `normalizeUserPreferences` silently discards legacy bare-string skills from existing local
  stores — expected: they were the unresolvable-GUID bug. Clear
  `yoma.discovery.preferences.mock` / `.anonymous` when testing migrations of shape.
- The mock-removal list (2026-08-27-c) grows one line: also remove `DEV_PREVIEW_HOSTS` and the
  hostname check in `api/services/userPreferences.ts`.
- Storage keys unchanged from `2026-09-02-a.md` Testing-state gotchas.
