## Gotchas

- Grouping and ordering are presentation concerns only. They must never be added to the signed provider schema.
- Static presentation metadata is developer-controlled through migrations; schema-admin requests cannot change it.
- Custom-field presentation remains controlled by custom-field configuration.
- System properties intentionally have null presentation metadata because they render in the fixed header.
- Static presentation metadata remains nullable. Configured groups render first and any unconfigured detail
  attributes safely fall back to display-label order.
- Wallet attributes consolidate core and custom fields into the same ordering space. Final custom-field
  configuration must coordinate exact group/subgroup labels and sort orders with the seeded core properties.
- Historical credentials immediately use current presentation metadata while retaining their exact issued schema/version.
