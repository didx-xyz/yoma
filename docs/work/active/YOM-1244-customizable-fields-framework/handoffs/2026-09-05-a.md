## Gotchas

- **The de-duplication is an intersection, not a fact.** With two or more types selected, a
  definition that all of them return is filed under "Details (all types)" even if it is
  type-specific to each — the endpoint gives us nothing better (API ask #1). With one type
  selected nothing is intersected.
- **`useTypeDefinitions` deliberately re-declares the query key and fetcher** of
  `useOpportunityCustomFieldDefinitionsQuery` (hooks cannot be called in a loop; `useQueries`
  can). If that hook's key ever changes, this one must change with it or the two will fetch the
  same definitions into two cache entries.
- **The banner's undo snapshot lives on the context, not in the banner.** Saving the last
  override can empty the query, which swaps `DiscoveryResults` for `DiscoveryLanding` and
  remounts the banner; component state would have taken the undo with it.
- **`useIsCompact` starts `false` and settles in an effect** (no `matchMedia` during render, or
  the server and the first client render disagree). A mobile reader therefore sees the desktop
  sub-group headings for one frame.
- **44px targets in the custom-field controls are opt-in.** `largeTouchTargets` is off by
  default so the admin and legacy filter panels are unchanged; a future caller that wants the
  bigger controls has to ask for them.
- The chip's `animate-pulse` survived the "remove every shimmer" sweep on purpose: it marks the
  newly added chip, it is not a loading placeholder.
- **A `ScrollableContainer` inside a flex parent silently stops scrolling.** It sizes to its
  content as a flex item, so `overflow-x-auto` never engages and the row overflows the page
  instead. Give the wrapper a width (`block`, or `min-w-0` plus `grow`) — the hero's quick-search
  row was broken this way between `md` and ~1350px. Worth checking the next scroller added.
- **404 ≠ failure.** `lib/apiStatus.ts` is the one place that decides; lookups carry
  `status[key]` and the definitions hook carries `unavailable` separately from `failed`. If a
  future facet is added, give it a status or it will report an environment gap as an outage.
- The headless harness lives in `/tmp/yoma-harness` (scratch, not the repo). Its clicks run
  through the DOM (`el.click()`), and the write-back offer needs ~10s of settle before it exists
  — several early runs looked like a broken save when the button simply was not there yet.
  Since the PWA revert, it also needs `page.setBypassServiceWorker(true)` or the dev service
  worker answers requests that request-interception never sees.
