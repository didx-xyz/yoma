## Why This Was Done Now

Both preset tickets are blocked on the API and on YOM-1264, and will stay blocked for a while. The
custom-field expansion has meanwhile put the existing opportunity search page, filter popup and
result card in question: the definitions endpoint now returns type-conditional groups with their own

Designing while blocked is the point. It gives the client and the team something concrete to react to
before implementation starts, and it turns several BA gaps into visible decisions rather than
surprises found during the build.

## Decisions Worth Reading Before Implementing

Full lists are in the two feature docs. The four that change scope or behaviour:

1. **A new page and component tree, not a refactor.** The existing discovery page, filter modal and
   badge components are not to be modified. Shared building blocks may be extended additively.
2. **Breakpoint parity is enforced by a test, not by prose.** Both containers consume one registry;
   a unit test asserts identical ordered section ids. This exists because the first design revision
   claimed parity and did not have it.
3. **Goal stays single-select**, `Attend events` is added, `Start a business` ships inert with a
   COMING SOON badge modelled in the registry.
4. **Compact list is a youth-controlled view**, in the URL, changing no query — and in it, every
   uploaded image and any future per-type layout has no effect. Worth saying to the client out loud.

## Gotchas

- **`types` binds the `Type` enum name**, never the type GUID. A GUID silently returns only generic
  definitions, with no error. The brief repeats this because it fails quietly.
- **Option filters submit option keys, not ids; Option + `Equals` uses the scalar `value`; `AllOf`
  only where `supportsMultiple === true`.** All three raise a hard `ValidationException` rather than
  returning nothing.
- The definitions endpoint returns definitions **already ordered**. Render that order; a client-side
  comparator would be a second source of truth.
- Accessibility preferences are sensitive: opt-in, internal to Yoma, excluded from every outbound
  payload, credential and analytics event — including the fact that the filter is on.
- The canvas uses literal hex because an artboard has no token pipeline. Map to the app's real tokens
  during implementation and report what was mapped.
