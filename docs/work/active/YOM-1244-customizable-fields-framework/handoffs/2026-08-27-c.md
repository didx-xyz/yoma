## API-contract findings — the design gives these up ("the API contract wins")

Verified by reading `OpportunitySearchFilter(Base).cs` and `OpportunityService.Search` on this branch:

1. **Sort**: `OrderInstructions` is `internal`, default `DateCreated desc`. Only **Newest** works;
   *Ending soonest* / *Most ZLTO* ship visible-but-disabled with a tooltip.
2. **Commitment-interval null rule is inverted vs the BA sheet**: the interval filter requires
   `CommitmentIntervalId.HasValue`, so opportunities with no commitment are **excluded** — the BA
   rule says included. The UI copy states the actual behaviour.
3. **No core facet** for Skills, Who it is for, SDGs, Accessibility — those sections render
   visible-but-inert with a pending note (`binding: null` in the registry). Same for the
   *Paid & remote*, *No experience needed* and *With accommodations* quick badges, and the card's
   pay line (salary / partner incentive / is-paid are pending YOM-1264 fields; the full precedence
   is already typed in `money.ts`).
4. **Facet counts** exist only on the category lookup; other sections show no counts (zero-grey-out
   applies to categories and the tiles).
5. `TotalCountOnly` is `internal` — the live count fetches `pageSize: 1` and reads `totalCount`.
6. `ApplyUserPresets` already exists on `OpportunitySearchFilter` (public on the derived class,
   ignored until YOM-1258) — the client-side `preferenceMapping.ts` is the mock-era stand-in for it.

## Gotchas

- `useDiscoveryQuery` re-parses `router.query` inside `dispatch` (not the memoised state) so two
  dispatches in one tick don't clobber each other.
- `useViewMode` restores the per-device choice only when the URL carries no `view` — URL wins;
  the restore is a one-shot effect keyed on router readiness.
- The reducer's `setType` clears `customFields` — type-scoped clauses never silently survive a
  type change. Anything new that changes the type must go through that action.
- `buildSearchFilter` is shared by the count, the results and the rails — if the request shape
  changes, change it there only.
- The definitions query sends **enum names** (`types: [state.filters.type]` where type is the
  name from `OpportunityType.name`); the search request maps the same name to a GUID via
  `typeIdByName`. Confirm once in the network panel during the browser pass.
- `DiscoverySurface` renders both filter containers, CSS-gated (`hidden md:contents` /
  `md:hidden`) — both mount, one shows. Cheap, and it is what makes the parity structural.
