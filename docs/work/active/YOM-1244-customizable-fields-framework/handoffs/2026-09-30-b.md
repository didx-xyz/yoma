## Where the canvas was deliberately NOT followed

The brief requires this list. "Existing implementation wins" means the brief's own rule 1, or
data the payload doesn't carry.

- **i18n:** the web app has no i18n (no `useTranslation`, no locale files). New strings are
  plain literals, like every existing one.
- **Categories:**
  - the lookup has full names only, so there are no short names;
  - icons are the lookup's own badge SVGs, since a colour filter turned them into blank discs;
  - categories the preferences supply are filled purple-tint, by the colour rule. The brief
    says "selected = green" only for this search's own picks.
- **Current filters:**
  - chips now wrap inside the frame, as in the canvas; the old row was one drag-scroll line;
  - chip labels stay "Group: value", and the button stays "Clear filters";
  - the zero-results state still repeats the chips inline. That's the 2026-09-05 decision, so
    with 0 results there are two instances.
- **Mobile bar:** the pill keeps its title and summary; the green Filters button sits beside it;
  My opportunities stays.
- **Banner:** content unchanged ("placement only"). The canvas's compact mobile banner is not
  applied.
- **Card type button copy** is the existing `getTypeConfig().ctaText`: "View event →" and "View
  impact action →", not "Register" and "Start task". Colours follow the discovery type chip:
  Event orange, Impact purple-light.
- **Card badge:** only "Ending soon" and "Featured", the signals the card already has. "No
  experience", "Certificate" and "Free entry" would need new rules, or keys that aren't
  system-controlled.
- **Card facts:**
  - Job shows employment only. `jobMinimumQualification` is not system-controlled, the same
    reason "No experience needed" is parked.
  - Facts the card already shows in another slot (money, place, places) are skipped.
  - There's no initials fallback when an org has no logo (existing behaviour).
- **Detail header:** keeps the existing meta row, not the canvas's money / employment summary
  line.
- **Detail sections:**
  - **Placement:**
    - "Skills you will learn" (non-Jobs) sits under Impact; "Skills required" (Jobs) under
      Requirements, open by default;
    - "How much time you will need" sits under Overview.
  - **The canvas's notes are not added** (new copy): "Checked against your profile's date of
    birth", "Informational — anyone can apply", "You're in range", and Minimum qualification
    as its own section (it lives in Additional details).
  - **New labels:** Age range rows use "Minimum age" and "Maximum age".
- **Provider card:** the provider text only. There's no org profile, "verified since" or "All N
  opportunities", because the payload has none of them.
- **Admin header:**
  - Deactivate and the other actions stay in the existing "Manage opportunity" menu, next to a
    new Edit button (same pull-sync, deleted and inactive-org rule as the menu's).
  - The stats are views plus the existing participant figures. There is no "applications"
    field.
- **Welcome step:**
  - The copy is Jason's draft and needs copy review.
  - Type tiles and quick searches have **no counts**: the API has no per-type count, and a
    request per tile breaks the no-fan-out rule.
  - "Six quick questions, about a minute" is not added.

## Gotchas

- **The global `* { scrollbar-width: thin }` is unlayered CSS.** It beats every Tailwind v4
  utility, so a hidden scrollbar needs `style={{ scrollbarWidth: "none" }}` (see the tabs and
  the welcome type row).
- **`pages/opportunities/[[...query]]` swallows any `/opportunities/a/b` that has no page.** A
  link to a route not yet built opens the legacy search page. `[opportunityId]/experimental.tsx`
  outranks the catch-all once it exists.
- **The card facts and the band badge key only on protected CF keys and existing status
  signals.** Add a fact or badge in `cardFacts.ts` / `cardStatus.ts`, never in the card.
