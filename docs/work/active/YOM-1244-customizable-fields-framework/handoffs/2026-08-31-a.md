6. **Wizard count copy** — the caption now reads "opportunities match your answers so far", an

7. **Card field set** — the card now promotes: type badge + reward · title (clamp-2) ·

### The participant-limit finding (§7 asked for this explicitly)

`OpportunityInfo` exposes **both** `participantLimit: number | null` **and**
`participantCountTotal: number` (plus pending/completed splits and `participantLimitReached`).
So "X of Y places left" renders from exposed fields only: `max(0, limit − countTotal)` of
`limit`, shown only when a limit is set. No client-side inference from anything else was needed.

### What needed JSX rather than a data edit (§8 asked for this explicitly)

- The **"More filters" disclosure** — one new button + conditional render in `FilterPanelBlocks`
  (~25 lines, once). The section trim/demotions/renames themselves were registry data.
- The **recents typeahead** — moving a block into the input is a component change by nature:
  `RecentSearchesPanel` rewrite + a relative wrapper and focus state around the input.
- The **card field set** (§7) — inherently a layout change in `OpportunityCard`.
- **`MyOpportunitiesLink`** and the **`CategoryCarousel` wrapper** — new small components (the
  wrapper *deletes* the ~60-line tile grid in favour of the existing app component).
- In `StepBlock`, removing `paidWork` simplified the `pills` case to engagement-only — a
  branch deletion, not new JSX.

Registry diff for §3: **85 changed lines** in `filterSections.ts` — dominated by the new `group`
field on all ten entries, the removed "Who it is for" entry, and reorder moves; labels changed on
two entries ("Where" → "Location", "How you take part" → "Engagement").

## Same-day follow-up: first browser feedback (UI polish pass)

Jason ran the surface locally and sent screenshots; root causes and fixes, same session:

- **Hero not full-bleed** — `MainLayout` centres its child in a flex container, so the surface
  was sized to content. Root now claims `w-full`; the purple band is its own full-width element
  with `pt-20 md:pt-24` to clear the fixed navbar; inner content and `<main>` align on
  `max-w-7xl` (the old page's width).
- **Oversized headings and card titles** — `globals.css` styles bare `h1–h3` at up to
  `md:text-4xl`; every heading without an explicit size utility inherited that. All discovery
  headings now carry explicit sizes (`text-sm`–`text-lg`, `tracking-normal`).
- **Invisible search-bar values** — the hero's `text-white` cascaded into the white segmented
  bar; the values ("Any type", "Anywhere"…) were white-on-white. The bar now sets `text-black`.
- **Badges/chips downsized** across quick searches, type row, section options, sort/view
  controls, wizard pills, goal cards and applied chips (`text-xs`, tighter padding).
  ⚠️ Deviation recorded: the fixed `min-h-11` (44px) on dense desktop chips was dropped for
  visual size per Jason's instruction; the applied-chip remove/undo buttons keep their 44px
  targets. Revisit tap-target sizing on mobile in the browser pass.
- **Drag-scroll rows** — the quick-search hero rows and the category browser now use the app's
  existing `ScrollableContainer` (drag/touch, optional edge shadows). The category browser keeps
  the app's `OpportunityCategoryHorizontalCard` (with its count) — `CustomSlider` was swapped for
  `ScrollableContainer` per Jason's preference; still no bespoke carousel.
- **Personalization scroll containment** — only the wizard column scrolls
  (`overflow-hidden` on the dialog box, `overflow-y-auto min-h-0` on the column); the purple
  count panel stays put on both breakpoints. Step title reduced to `text-lg md:text-xl`.
