  Learning/Other; submit full `name`. No new selection endpoint, auto-save fallback or recommendation
  flag was added. Custom choices remain meaningful and later startups do not rewrite them.

### Startup and History

`SSISchemaName` is a string provider reference with no database foreign key. The migration can
assign canonical names before the existing `SeedSchemas` startup background job publishes them.
No assignment update runs after startup. As usual, wait for successful schema seeding before
release sign-off or testing the scoped schemas. If publication fails, normal schema validation
and issuance error/retry handling applies; do not silently revert assignments to generic Default.
This does not add a synchronous startup readiness barrier or change retry limits.

Scheduling commits **schema name, schema type and artifact type**, not schema version. Existing
Pending/Error work retains that name after its Opportunity's reassignment; processing resolves the
latest version of that stored name. Therefore an old generic queue can use the revised generic
schema but is **not redirected** to the scoped schema and does not acquire scoped CFs/Job-specific
skill exclusion merely because the Opportunity changed. Stage 3 below now handles exact attempt
identity and provider-success recovery. Issued credentials keep their issued identity/version and no
replay, deletion or new schedule was performed.

The migration is still undeployed and amended in place. Jason must down/reset/recreate Local;
already-migrated Local/Dev databases do not pick up the reassignment on a restart. Stage/Production
get the one-time migration when this release is deployed, then the normal startup schema seed.
No shared-environment database or live provider was modified during this work.
