## What Was Done

Jason asked for one enhancement and two bug fixes. Kept small, as Jason asked.

1. **Wizard step 2 shows category icons.** Each interest pill draws the category's own icon
   (`imageURL`), as Browse by category does. `PreferenceOption` and `Pill` each take an optional
   `imageURL`, and the chips block passes it on. Pill text is left-aligned now, so a name that
   wraps at 320 sits beside its icon.
2. **Anonymous answers last in every tab.** `userPreferencesLive.ts` reads and writes
   `yoma.discovery.preferences.anonymous` in `localStorage`, not `sessionStorage`. The cause:
   the "seen" marker has been in `localStorage` since 2026-09-05, but the answers stayed in the
   tab that saved them. So a new tab had no answers, kept the wizard shut, and asked through the
   "Tune your feed" banner. Jason accepted that answers, accessibility needs included, now stay
   on the device until the sign-in offer keeps or discards them.
3. **Results only once the search has a filter.** The surface and `useChipPulse` read the
   context's `hasFilters` (`hasActiveFilters`). `isDefaultDiscoveryState` is removed.
   - `prefsOff`, `prefsSkip`, the sort, the page and the view no longer make results. So
     `?prefsOff=1` is the landing with preferences off. Clear filters after a rail's See all
     lands on the landing, and the master switch on the landing only shows or hides "Picked for
     you".
   - "Latest opportunities" has no See all any more. Its set had no filter (`?prefsOff=1`), and
     Jason chose against a new `all=` parameter. `seeAllOf` in `DiscoveryLanding` draws no See
     all for a filterless search.
   - Clear filters still leaves preferences as they are (2026-09-05, confirmed by Jason).
4. **Docs:** `feature.md` (Status, Tasks, a 2026-10-07 Decisions entry), the epic README row,
   this handoff. Comments that named `sessionStorage` for the anonymous answers are updated.

## Gotchas

- **The landing rule is `hasActiveFilters`, nothing else.** Anything that should show results
  must put a real filter in the URL. A See all that would carry none must not be drawn: go
  through `seeAllOf`.
- **Old recent searches** saved as `prefsOff=1` (the old "All opportunities" entry) now replay
  to the landing. They exist only in testers' browsers; nothing cleans them up.
- **An open tab doesn't see answers saved in another tab** until it reloads. The anonymous query
  is cached with `staleTime: Infinity`. No `storage` listener was added.
