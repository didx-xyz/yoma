## Gotchas

- **Two preference layers in the context.** `savedFragments` is the preset as saved, used only for
  the chips. `fragments` is the layer without the interests skipped one by one, used for
  everything that composes a search. Use the saved one anywhere else and a skipped interest
  comes back into the search.
- **The Filters badge counts this search's own filters only** (manual chips and custom-field
  clauses), never the preferences.

- **`ScrollableContainer`'s scroller must stay its wrapper's FIRST child.** `CustomCarouselV3`
  finds it by DOM position (`> div > div:first-child`). Anything added to the wrapper goes after
  it, or V3's lazy loading, snap and styles silently target the wrong element.
- **The card is a fixed-height flex column.** Every row is `shrink-0` so overflow can't squeeze a
  clamped row. Adding height to any row means raising `h-74` / `md:h-88.5` here AND the rail
  placeholder in `DiscoveryRail` to match.
- **`all` is a facet that filters nothing.** `buildCriteria` never sends it, so a URL with
  `all=1` asks the API exactly what the same URL without it asks. Don't send it, and don't count
  it in the Filters badge (`filterCount` excludes it).
- **Freshness is one constant** (`DISCOVERY_STALE_MS` in `useDiscoveryResults.ts`), shared by
  results pages and counts. Lowering it brings back the refetch Jason saw.
- **The count's cached seed only applies while its debounced key is the current search's**, so
  a total never lands on another search's key.
- **Bleed the carousel's wrapper, never its scroller.** The fades are pinned to the wrapper.
