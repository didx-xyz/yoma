## Gotchas

- **The API rejects unknown members.** A new search field has to be added to the converter's
  member list for each endpoint, or the request 400s.
- **Worldwide and the Business category are request-only.** Never put them into
  `effectiveFilters`: the Where section locks region, city and distance on a second country,
  and the category would read as an AND with the type.
- **Inherited accessibility needs are private.** They never reach the URL, chips, headings,
  recent searches or the mobile pill by name. See all strips them; the chip reads "your needs".
- **A manual value that duplicates an inherited one keeps the inherited mode** (Jason's
  call). The Remote quick search while Remote is inherited stays `Include`.
- **Readiness.**
  - A search with preferences on waits for the preference layer, so its first request is never
    replaced.
  - Searches with preferences off and the default rails don't wait.
  - Any new discovery request should go through `searchReady` / `preferenceSearchReady`.
- **The count body has no `ordering`.** Parity is "the results body minus paging and ordering,
  plus `totalCountOnly`".
- **`pnpm test` loads pure modules only.** `api/services/opportunities.ts` pulls in axios,
  next-auth and env, which is why the converter lives in its own module. Run it through mise
  (Node 24).
- **Ship W1–W3 together.** W1 alone lets the API's new defaults flip provider, engagement and
  commitment under stale copy.
