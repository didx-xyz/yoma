## Gotchas

- **Never resolve skills per card.**
  - `CustomFieldsView`'s `resolveSkillsById` is for single-instance hosts.
  - A list that needs names should collect its IDs at list level and call `useSkillLabeler` once.
- **`POST /lookup/skill/ids` rejects the whole request** for an empty array, a malformed ID or the
  all-zero GUID. `skillIdsToResolve` filters them, so go through it.
- **`useSkillLabeler` folds each response into state during render** (the "information from
  previous renders" pattern), guarded on the response's reference. Adding a `select` to that
  query would change the reference every render and loop.
- **Custom-field groups are one level now.** Discovery's one-group rule counts distinct `group`
  values; never compare a group's text. A future `subGroup` still renders (the sub-group rule is
  kept inside).
- **The API's default youth order is `DateStart` descending.** It is not the date created,
  whatever the 2026-10-05 handoff says.
- **CDP `Network.setBlockedURLs` persists** in the throwaway browser's session. Restart it after
  simulating a failure.
