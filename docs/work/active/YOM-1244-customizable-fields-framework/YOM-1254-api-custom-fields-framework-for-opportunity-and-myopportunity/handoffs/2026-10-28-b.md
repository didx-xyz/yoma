## What Was Done

### Completion and reward totals

- Ported the released fix onto refreshed master without replacing master's newer CF/location/provider branches or reintroducing removed migration/live-environment test fixtures.
- Ordinary single/batch Opportunity and Organization edits no longer overwrite lifecycle-owned totals from stale models. Dedicated `IRepositoryTrackingTotals` and batched/composed interfaces expose totals-only writes; existing base interfaces are unchanged. All consumers, constructors, tests and DI registrations use the most-derived interface consistently.
- Metadata updates copy the loaded entity's totals into the returned domain model for API/event consumers. This is explicitly a loaded snapshot, not a fresh post-save database read. Only the totals writer mutates the entity totals. Queried entities use ordinary EF change detection, without UpdateRange or manual IsModified flags.
- Reward allocation and organization financial-year resets use the dedicated writer. Reward limits, calculation, locking order, authorization and downstream work are unchanged.
- Reused the existing shared execution-strategy cleanup at owning instant/partner/CSV completion boundaries and standalone finalization/allocation. Nested ambient work does not clear its owner's context. No shared retry-handler rewrite was needed.

### CSV migration and package refresh

- CsvHelper 33.1.0 -> 34.0.0. The former Production version-only upgrade was intentionally not repeated: v34 replaces reader/writer configuration, mapping, converters and error APIs.
- Both import DTOs now use native CsvRecord source-generated mappers and renamed CSV metadata. Internal CF/field-presence state is explicitly ignored by the mapper.
- Preserve comma/invariant imports, fixed header requirements, aliases, optional dynamic CF columns, blank optionals, pipe-delimited lists, missing-required-cell reporting and probe/commit flow. Header reading does not consume the first data record. Quoting/conversion errors still become row errors before domain processing; conversion errors retain field/value information. v34 reports physical spreadsheet line numbers, including multiline fields.
- Keep Yes/No, True/False and numeric 0/1 boolean inputs, including forms the old integer parser accepted; do not silently enable v34 shorthand y/n/t/f. Empty optional booleans stay null.
- The shared export helper retains public computed/get-only columns, ignored properties, aliases, declared order, culture-dependent separator/date/decimal formatting, Yes/No, UTF-8 BOM, CRLF and whitespace quoting. Native v34 generated writers would otherwise omit existing computed columns. Export metadata is cached per DTO type; no parallel export model or dependency was added.
- Refreshed all outdated direct packages in the API solution to the latest stable feed versions: Microsoft/EF 10.0.14, libphonenumber 9.0.42, StackExchange.Redis 3.4.20, AWS setup 4.0.102.7 and S3 4.0.104.7. Other direct references were already current. A final solution-wide outdated-package check returned no outdated direct packages. No SDK, frontend, Helm, CI, secrets or configuration changes.

## Gotchas / Open Questions

- Normal metadata writes must never regain assignments to ParticipantCount or reward cumulatives. New lifecycle-total writers must opt into the narrow capability and use the existing transaction/lock rules.
- Clearing tracking inside a nested operation can detach its owner's pending work. Cleanup belongs to the outer durable transaction attempt, including rollback/retry and CSV probe boundaries.
- v34 header lookup also supplies its own case/whitespace matching fallback. Templates keep the same canonical column spellings and fixed-header validation; do not introduce extra business aliases.
- Do not recompute financial-year totals from DateCompleted. Historical seeds copied lifetime totals into year balances; any future repair must reconcile award schedules and rollover history separately.
