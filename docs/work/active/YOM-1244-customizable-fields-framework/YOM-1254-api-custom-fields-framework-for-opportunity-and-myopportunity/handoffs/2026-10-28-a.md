## Gotchas

- This proves mechanisms in released persistence components, not the exact historical request which caused HOT Opportunity 4's 252-versus-486 discrepancy. Live migration history and live reward drift were not queried.
- Do not change the shared cleanup default globally or clear tracking midway through an outer transaction. Required nested allocation/finalization must not own cleanup; an explicit RequiresNew entry point owns its own transaction.
- Metadata writes must never persist completion counters. Conversely, the dedicated total writers must not persist stale titles, pool configuration or other metadata from their snapshots.
- Financial-year reset must still zero only current-year totals, preserving lifetime totals. Its dedicated batch writer assigns only totals/audit fields on tracked entities and relies on EF change detection and normal SaveChanges batching; do not reintroduce UpdateRange to force every scalar modified.
- Treasury awarded-ZLTO totals include referral rewards as well as opportunity rewards. Cash-out USD cumulatives are separate. Use award/allocation timing for financial-year audits rather than blindly using backdated imported completion dates.
