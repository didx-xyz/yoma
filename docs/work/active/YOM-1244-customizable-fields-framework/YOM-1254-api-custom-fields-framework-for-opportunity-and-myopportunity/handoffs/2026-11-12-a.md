## Finding and fix

Production audit supplied by Adrian confirms 808 completed verification records and 575 stored completions: deficit 233. The UI agrees with the stored counter. This is a counter discrepancy, not evidence that completion records disappeared.

The previous metadata/total separation and opt-in tracker cleanup from PR #2008 remain present. However, JobJack and IXO PartnerSync register `IExecutionStrategyService` after the application database registration. Default DI resolution selects IXO's strategy, whose cleanup clears IXOPartnerSyncDbContext, not ApplicationDbContext. Accepted EF state from a rolled-back CSV validation row survives into the next validation/import operation. Equal proposed totals can then be treated as unchanged even though the database rolled back.

The original defect fix changes four production files:

- `src/api/src/infrastructure/Yoma.Core.Infrastructure.JobJack/Startup.cs`
- `src/api/src/infrastructure/Yoma.Core.Infrastructure.JobJack/Services/OpportunityFeedBackgroundService.cs`
- `src/api/src/infrastructure/Yoma.Core.Infrastructure.IXO.PartnerSync/Startup.cs`
- `src/api/src/infrastructure/Yoma.Core.Infrastructure.IXO.PartnerSync/Services/OpportunityCatalogueBackgroundService.cs`

Both provider strategies are registered and injected concretely, following the existing Alison/Jobberman/Aries/Substack pattern. Domain services continue to consume the shared interface bound to ApplicationDbContext. No shared retry/transaction implementation, repository contract, business rule, package, schema or frontend changes.

Adrian subsequently requested the same pattern for Umuzi. Its dedicated interface was already safe, but is now removed for consistency. Umuzi Startup, its handler and catalogue-service constructor use concrete registration/injection; the shared interface remains inherited through ExecutionStrategyServiceBase. Include these Umuzi changes in the forward-port. The regression fixture now also registers Umuzi last and checks that its cleanup leaves application and IXO tracking intact.

All remaining unkeyed strategy registrations were searched: only Database Startup remains. Existing CSV probe/commit, manual finalization, instant completion and partner verification boundaries already request cleanup at the owning transaction boundary; those calls are unchanged.
