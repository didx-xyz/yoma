## Decision and Scope

- The 1 September credential deck labels Entrepreneurship v0.1 as a partner-issued draft without a Yoma Opportunity. Mpho's later 4 September reply explicitly confirms a **new Entrepreneurship Opportunity type** for the current Yoma Core path. Completion can be manual, CSV, Partner Sync or an instant action, but only the first three currently carry completion CF values. No standalone VC import or partner-direct issuance is introduced.
- New opportunities can select the existing generic `Opportunity|Default` schema. The Entrepreneurship-specific schema, credential attribute mapping and partner issuance contract remain the final CF phase.
- Core Opportunity fields still supply organisation, programme title/summary, category, country/location, language, skills, verification and engagement type. The programme's location is not asserted as the youth's venture location. Business revenue is not the Opportunity's `Incentivized` reward.

## What Was Done

- Added the `Entrepreneurship` enum and seeded lookup ID `d74da423-7779-4f49-9d6b-92ce5f61f4a1` in the consolidated, undeployed CF configuration migration. The temporary legacy Difficulty SSI projection explicitly has no value for this type.
- The new CF seed rows now use the migration execution time (`DateTimeOffset.UtcNow`) for creation timestamps, consistent with existing lookup seeding; no fixed September 2026 timestamps remain in the CF seed helpers.
- Manual Entrepreneurship Opportunity capture may omit `Incentivized` and both commitment fields. If an incentive is offered, the existing Reward Type/amount/currency consistency rules still apply. If commitment is supplied, interval and count must be paired. All other common core validation remains unchanged.
- Manual Entrepreneurship verification may omit a participation start date or commitment estimate; the existing completion end-date default/validation remains. A supplied commitment interval still requires a valid lookup ID and positive count. CSV/Partner Sync auto-finalized verification already permits incomplete period data.
- Seeded optional Opportunity CFs: `entrepreneurshipProgrammeType` (known programmes plus Other), `entrepreneurshipProgrammeOtherDescription` (required only with Other), and `entrepreneurshipVentureStageTargeted` (four stages). The Other pair is checked against the merged Opportunity state, including CSV/Partner Sync patches.
- Seeded MyOpportunity CFs. Manual verification requires **Business / venture name**, **Business summary** and **Business registered** (Boolean, allowing informal ventures). CSV/Partner Sync patches may omit missing fields under the existing import mode. All other rows are optional:

  | Key | Meaning |
  | --- | --- |
  | `entrepreneurshipRegistrationReference` | Number/document reference when registered; no forced number for informal ventures. |
  | `entrepreneurshipSector` | ISIC Rev. 5 Section; copies the seeded Job Industry option keys/labels at migration time. |
  | `entrepreneurshipJobsCreated` | Non-negative count excluding the founder; zero is valid. |
  | `entrepreneurshipRevenueBand` | Monthly USD-equivalent band, including `PreRevenue`; omitted means unknown. This captures the deck's income-generated distinction without a second Boolean. |
  | `entrepreneurshipRevenueCurrency` | Optional ISO currency lookup for the business's reporting currency; does not change band thresholds. |
  | `entrepreneurshipFundingTypes`, `entrepreneurshipFundingAmountBand`, `entrepreneurshipFunder` | Optional summary of funding actually secured. Types may be multi-select; band and funder are one aggregate summary, not a repeatable funding-transaction model. |
  | `entrepreneurshipClientLocation` | Broad customer reach, not the venture's physical location. |

- Did not add separate CFs for issuer, verification/evidence, Skills Earned or venture location. Existing core fields/verification evidence cover the first three; the BA sheet explicitly deferred venture-location capture. No partner-specific mapping is guessed.

## Jason's API Contract

1. Retrieve Opportunity definitions with `GET /opportunity/custom/field/definition?types=Entrepreneurship`; submit the complete `customFields` collection on create/update. Inline Option fields submit option **keys** in `values`; scalar fields submit `value`. The shared Currency lookup submits its **GUID** in `values`.
2. Retrieve completion definitions with `GET /myopportunity/{opportunityId}/custom/field/definition`. Manual verification sends `customFields` as the existing JSON-encoded multipart field. Show the three required business fields; only show Other programme text when Other is selected. Registration is Yes/No, not a compulsory number.
3. The current generic Default credential does not yet display Entrepreneurship-specific CFs. Do not imply that completing a form has already made those facts part of a VC. The existing instant action flow intentionally skips CF capture, so it is not suitable for rich venture outcomes until that flow is designed explicitly.

## Gotchas

- Opportunity core `DateStart`, title, description, summary, organisation, category, country and language are still required. `DateEnd`, engagement, region/city/coordinates and skills are optional. `VerificationEnabled` must be true for completion and the existing rules pair it with credential issuance and a selected SSI schema.
- The Job and Entrepreneurship ISIC options have separate CF option rows but the same keys/labels. Inline option keys, not generated row IDs, are the API contract.
- The latest email trail rejects `not available` placeholders in signed credentials. Required MyOpportunity fields are enforced for manual submissions; external patches may remain incomplete, and the final credential schema must include only guaranteed facts.
