### Production code changes

- `SSICredentialService.ListPendingIssuanceSchedule`: require Created user/organization tenants with non-empty provider IDs for Opportunity work in the SQL predicate **before** ordering/Take. Use existing `IRepositoryBatchedWithNavigationAndCustomFieldFilter<MyOpportunity>` and `IRepository<SSITenantCreation>` registrations; no new repository abstraction or DI alias. Case-insensitive tenant entity types align with existing tenant lookup. Correlated existence checks do not hydrate full completion/opportunity children for rejected rows.
- Blocked rows are untouched: no status, retry, timestamp, schema or credential mutation. Once mappings become ready they can be selected on a later run. YoID selection retains its existing path. Existing per-item tenant rechecks handle a mapping changing after SQL selection.
- Preserve Pending/status filtering, per-run skip list and modification-date ordering, adding ID as a deterministic tie-breaker. Do not add present-day opportunity publication, enablement or schema gates: scheduling already committed the schema name/type/artifact.
- `SSIBackgroundService.ProcessCredentialIssuance`: include scope creation, DI resolution, processing and scope disposal inside the slot-release guard. Fatal setup/infrastructure/persistence exceptions stop dispatch. Always await all started workers in a producer `finally` before semaphore disposal/distributed-lock release.
- Inject `IHostApplicationLifetime`; keep the public parameterless job signature so previously serialized Hangfire invocations remain compatible. Host stopping cancels waits/new dispatch and leaves unattempted rows Pending without consuming retries. A disposed dependency stops the run instead of exhausting per-credential retries. Escaping fatal errors are rethrown for Hangfire failure visibility.
- Provider calls have no cancellation-token contract and are not forcibly interrupted. If one already succeeds during graceful shutdown, persist its credential/schema metadata before ending. Hard termination can still happen; existing client-referent recovery remains responsible for provider-success/local-save uncertainty. No exactly-once delivery claim is made.
- Ordinary provider/validation errors still use the existing error/retry policy and per-run exclusion. Scheduled names, latest-version resolution, recovered historical schema identity, signed claims and wallet contracts are unchanged.
- Added eligible-batch counts and final issued/failed-attempt counts to the existing info logging, with an explicit shutdown warning. A completed scan does not mean blocked Pending rows have been issued.

No global cache replacement/recreation, Hangfire activator changes, new dependencies, migrations, UI, Helm/config or provider changes were made. The Yoma API style skill kept the implementation within existing service/repository conventions.
