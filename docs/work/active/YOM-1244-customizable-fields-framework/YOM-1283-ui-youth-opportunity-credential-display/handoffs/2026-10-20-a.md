## What Was Done

Two rounds in one session, both from Adrian's Stage review (2026-10-20, shared outside the repo)
and Jason's direction.
The decisions and their reasons are in `feature.md` (2026-10-20 entries); this is the summary.

**Round 1 (lead, no roles)**

- **BA palette.** Type colours from the BA Review workbook (Yoma Credentials sheet) as
  `--color-type-*` tokens, consumed only through `lib/typeColours.ts`. That module replaced
  discovery's `typeBadge.ts`, so discovery took the palette too. Hex table in `feature.md`.
- **`typeContext`** added to the web wallet model; a credential's type comes only from
  `schemaType` (YoID) and `typeContext` (`credentialTypeKey`), neutral when neither identifies it.

**Round 2 (agent roles)**

- **Design spec**, approved by Jason with his answers:
  [design/2026-10-20-yoid-discovery-alignment.md](../design/2026-10-20-yoid-discovery-alignment.md).
  The designer's build comparison is its §11.
- **Cards.** One card language, discovery's: shared pieces in `lib/card.ts` (grid, band, logo, chip,
  title, action). `CARD_GRID_CLASS` is 1 column below 600px, then 2/3/4 at 600/900/1200px, so no
  card is wider than 425px from 600px up; discovery's results grid and skeleton use it too. YoID
  opportunity cards (`OpportunityListItem`) and passport cards (`CredentialCard`) follow it.
- **Passport** (`pages/yoid/passport/[[...query]].tsx`, `components/Credentials/PassportCredentials.tsx`,
  `lib/credentials/credentialGroups.ts`): chips (All + one per type), inline type sections (one row
  each under All, "See all n →" selects the chip), additive "Load more credentials" (100 per load,
  `useInfiniteQuery`; a failed load keeps the cards and offers Retry), Jump to top. No carousel, no
  pager. Detail modal: header in the type colour ("<TYPE> · YoID"), fixed while the body scrolls.
- **YoID shell and pages**: discovery's hero band with the world-map stencil, pill tabs with io5
  icons (`components/YoID/yoidTabs.ts`, `components/Common/PillRow.tsx`, `lib/pill.ts`),
  breadcrumbs kept without emoji (`YoIDBreadcrumb`), overview and wallet tiles through one
  `YoIDTile`, opportunity sub-tabs as pills with counts, overview summary 2 × 2 on phones (fixes the
  320px overflow), skills tile capped at 8 + "+N more", passport tile no longer overlapping its stamp.
- **Breadcrumb** (`pages/opportunities/[opportunityId]/index.tsx`): `router.back()` only when the
  previous in-app page was `/opportunities/discover` (`lib/previousRoute.ts`, tracked in `_app.tsx`),
  else the link's own `href` (`OPPORTUNITIES_SEARCH_URL`). `experimental.scrollRestoration` in
  `next.config.mjs` restores the results position — tester measured y=1658 before and after.
- **Types lookup**: the passport and YoID cards use the existing `useOpportunityTypesQuery`, now
  with `staleTime: Infinity` (also affects the two admin opportunity pages: one fetch per session).
- **TEMPORARY passport mock** for `testuser@gmail.com`, local only: `lib/credentials/passportMock.ts`
  (130 credentials shaped like Adrian's reference) and `PASSPORT_MOCK_ENABLED` in
  `api/services/credentials.ts`. **Must be removed before push** — steps below.
- **Not built (Jason):** grouping, chips and per-type paging on the YoID opportunity pages, on hold
  until Adrian adds an opportunity-type filter to the youth MyOpportunity search (epic README,
  Cross-Area Notes).

## Gotchas

- **Local issuance is all Pending** for testuser (14 issuances, 20 tenant creations against the
  shared `cloudapi.test`); nothing was triggered.
- **The mock is client-side only** (`getSession()` email check, skipped when a server `context` is
  passed) and gated on `NEXT_PUBLIC_ENVIRONMENT === "local"`, but its fixtures are bundled while it
  exists — another reason to remove it before push.
- **Learning and Other are the same slate** by BA design; only the label differs. **Event `#391350`
  and YoID `#3b1251` are nearly identical** — the reviewer flagged it; it is the BA palette as given.
- **Scroll restoration is app-wide** (Next's `experimental.scrollRestoration`). Discovery's own
  router updates pass `scroll: false`; the legacy `/opportunities` page and admin forms still call
  `scroll: true` / `scrollTo(0, 0)` and win there.
- **Cards have no `overflow-hidden`**; the band rounds its own corners so badge tooltips escape.
- The design spec still names `lib/cardGrid.ts` in places; it is `lib/card.ts` now.
