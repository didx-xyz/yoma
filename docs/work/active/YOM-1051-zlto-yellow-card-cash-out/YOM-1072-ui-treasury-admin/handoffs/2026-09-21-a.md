## What Was Done

`/admin/treasury?tab=payouts`, over `POST /treasury/payout/transaction/search` and
`GET /treasury/payout/transaction/{id}`.

- **Contract** — `api/models/payout.ts` gained an admin section (`PayoutTransaction`,
  `PayoutTransactionSearchFilter`/`Results`, `PayoutTransactionAdminInfo`, `PayoutType`,

  the calls with the controller that owns the route and the Admin role.
- **Vocabulary and filter mapping** — `lib/payout/adminTransactions.ts`: per-status label, tone and
  a description of what the status means for the ZLTO; type labels; timestamp formatters; the
  display-filter → API-filter mapping (whole-day UTC bounds, empty lists to null, pagination always
  sent).
- **Components** (`components/Payout/`) — `PayoutStatusBadge`, `PayoutTransactionSummaryRow` (the
  list row) and `PayoutTransactionDetail` (the dialog body), all prop-driven, plus

- **The tab** — `components/Treasury/TreasuryPayoutsTab.tsx`: search, filters, badges, paging and
  the detail dialog, using the shared `ListPage*` kit. Wired into `pages/admin/treasury/index.tsx`

## Gotchas

- **The local environment cannot exercise this surface.** The API is up and its swagger confirms
  the contract, but the seeded admin (`testadminuser@gmail.com`) exists only in the API database —
  the Keycloak realm export carries no users and a password grant for it is refused. So no
  authenticated call was made from this session; the TypeScript contract was verified against
  `/swagger/v3/swagger.json` (field names, nullability, and that every enum is a string) rather
  than against a live response. A fresh local database also has no payout rows, and `?mock=` does
  not help — it substitutes the Treasury record only.
- **Two amounts, two units, both called "amount"** (the epic's own gotcha, and the single easiest
  way to get this screen wrong): `PayoutTransaction.amount` is USD, the linked
  `RewardTransaction.amount` is the ZLTO that was reserved. They are in separate labelled groups
  and use `formatUsd` / `formatZlto`. The row shows only USD — the ZLTO is not on the search
  projection, and reconstructing it at today's rate would be a lie for any older payout.
- **The provider is neither shown nor filterable**, deliberately. The API supports `providers` and
  the row carries `provider`; the field is typed and commented so it is a UI-only change when a
  second provider appears. Reason in `feature.md`.
- **`valueContains` searches more than it looks like.** Per
  `PayoutTransactionRepository.MatchingIds`, it covers the user's email, phone and display name,
  the provider reference and the error reason — and, when the typed value parses as a GUID, the
  payout id and the user id exactly. The placeholder says "name, email, phone or reference"
  because an admin pasting an id will find it anyway.
- **Correction to the epic README, 1: the branch note was out of date.**
  `feature/custom-fields-framework` was squash-merged into `master` as `20a4f268` (#1924) on
  2026-09-16. Verified: `20a4f268` is an ancestor of master, and no `Chimoney` identifier remains
  in the Treasury domain. The README now says to branch from master and keeps the old warning as
  history.
- **Correction to the epic README, 2: the "re-point the SHAs before the PR merges" item is
  overdue, not pending.** The merge already happened. Checked `70b2ccd`, `0d7a67ba`, `f051dfd8`,
  `48540971` and `08cb6c10a`: all still resolve in a clone that fetched the branch, **none is an
  ancestor of master**. They survive only where GitHub keeps the PR head. Nothing was rewritten —
  the item was corrected to say what is now true, and no new branch SHAs were cited anywhere in
  this session's docs.
