## Gotchas

Carry these forward — they have each cost time already.

- **Three Treasury figures, never conflate**: `payoutPool` (allocation) · `payoutBalance` = pool − cumulative (**COMPLETED-ONLY, not capacity**) · `payoutBalanceAvailable` = balance − pending (**capacity**). As of today both T1 surfaces read the third; if you add a capacity reading anywhere, use the same one.
- **Pending payouts survive a financial-year rollover; the cumulative does not.** Any floor or capacity arithmetic has to keep the pending half when the FY moves forward. This is the one thing the previous mirror got wrong.
- **The pending total is not returned by the API** — derive it as `completedBalance − availableBalance` via `lib/treasury/payoutCommitment.ts`. It is `null` when no pool is set; do not substitute `0`, and do not invent a client-side floor in that case.
- **`PATCH /treasury` and `PATCH /organization` are FULL REPLACEMENTS.** Omitting a pool clears it.
- **Server validation failures carry no field name** — per-field mapping is message-text matching. **Read the actual server string before adding a matcher**; the existing patterns are deliberately broad and may already cover a "new" message.
- **Permissions failures return HTTP 401, not 403**, so `ApiErrors` says "your session has expired" for what is actually a permissions problem.
- **Wallet: `balance` / `available` / `total` are NULLABLE** (null when the provider is offline); `pendingPayout` / `pendingRewards` are not. **Branch on `null`, NOT on `zltoOffline`.** `null + 5` is `5` in JS and `0` is a legitimate balance, so neither arithmetic nor truthiness is safe.
- **`total` = `available + pendingRewards`.** It never included `pendingPayout`.
- **Rewards have NO available-balance equivalent and never will** — they allocate at schedule time. Do not add one by analogy with Treasury. This is a *do not*, not a gap.
- **T4 must show Treasury ZLTO REWARD figures, not USD payout figures.** Pulling `payoutBalanceAvailable` onto a referral surface is a category error.
- **The `?mock=` dev aid is committed and must be removed before merge** — `lib/treasury/treasuryMockScenarios.ts` plus the three `⚠️⚠️ MOCK SCENARIOS` blocks in `pages/admin/treasury/index.tsx` (and `MOCK_PARAM`). The dev-only banner in `TreasuryOpportunitiesTab.tsx` goes with the tab rework.
- **The Opportunities tab is provisional** and its reduced scope is deliberate — no list endpoint exposes per-opportunity pool/balance (`OpportunityItem` has them but all `[JsonIgnore]`). Do not "fix" either without the API change.
