### What moved to the epic README

The cross-cutting material, so it exists in **exactly one place** and the feature docs link to it:
the load-bearing-branch note and its full commit history, the domain rules (FY vs lifetime,
server-derived balances, the rollover job, the ⚠️ null-pool-means-unlimited rule, ZLTO-only, enum
names not ordinals), the three-figure Treasury availability model with the cross-FY quirk and the
rewards-are-asymmetric warning, the `/admin/treasury` aggregation-point directive with the tab
table, the frozen T0 conventions, and the epic-wide blockers.

Three judgement calls worth knowing about:

1. **The validation digest was kept whole in the epic README**, not split across the four feature
   docs. Its value is that the diverging caps (100M Treasury / 10M Org / 10M Referral / 50k USD)
   sit side by side — that adjacency *is* the "never copy a limit from a neighbouring surface"
   protection, and splitting the table is exactly how it would be lost.
2. **T6 (production hardening) became an epic-wide section**, not a ticket task. It is an audit
   across all five tabs plus the `?mock=` removal; assigning it to one child would have hidden it
   from the other three. The same applies to the authenticated browser pass and the
   fold-Opportunities-into-Organisations item.
3. **A T-number → ticket map is in the epic README.** Every existing handoff talks in T0–T6, and
   those numbers do not map one-to-one onto tickets. Without the map, moving the handoffs would
   have orphaned every reference in them.

  `Tickets: YOM-1051 (epic) · YOM-1063 · YOM-1072 · YOM-1073 · YOM-1074` line. Both are replaced by
  the epic child table. The handoffs still carry `**Feature**: rewards-payout-ui` in their Meta
  blocks — left as written, since renaming them would be rewriting a contemporaneous record.
- **The `T0`/`T1`/… task labels as the primary organising key.** They survive as labels inside each
  feature doc plus the map in the epic README, but the tickets are now the structure.
- **The struck-through 2026-08-04 "epic paused at T2 pending Wall 1" decision.** It was already
  struck in place on 2026-08-05 and the gate no longer applies; carrying a struck entry into a fresh
  doc adds noise, and it is preserved in git history and in `2026-08-05-a.md`.
- **The 2026-08-05 "master's UI was ported web-only, with no merge parent" decision** as a standalone
  entry. It was discharged by the real merge on 2026-08-07, so both facts are folded into a single
  ordered branch-state list in the epic README rather than kept as a decision plus its retraction.
- **The 2026-08-05 "6 vs 8 fields" arithmetic** in T3's detail-block decision, already superseded by
  the Yoma removal taking `OrganizationRewardFigures` to four fields. The decision itself is kept in
  YOM-1063 with the arithmetic marked superseded rather than repeated.
- **Per-decision restatement of the general lessons** ("read the server string before adding a
  matcher", "delete the old field from the interface in the same change", "follow the code, not the
  tickets"). Each is now stated once — in the epic README's Shared Contract or Cross-Area Notes —
  and the dated ticket-level decision points at it instead of repeating it.

Two things were **added** rather than dropped, because the restructure surfaced them:

- YOM-1073's ticket asks for **hard validation** of a programme pool against Treasury capacity. The
  code has none. That gap was in the old Out of Scope list as one line; it is now stated in
  YOM-1073's Out of Scope *with the ticket's own wording quoted*, so nobody re-reads the ticket and
  assumes it was missed.
- The **provider name in the folder slugs**. The epic's binding rule is "never name a payout
  provider in user-facing copy", and the convention says take the slug verbatim from the Linear URL.
  Both hold at once — the README says so explicitly so nobody "fixes" the folder names.
