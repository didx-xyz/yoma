## What Was Done

Local/Dev and Stage share the ACA-Py test registry. YoID Default 1.0 contains the original Email
claim; CF-published 1.1 replaces it with AccountVerificationMethods. Stage's old catalogue maps
only nine of its ten public attributes. Schema listing validates every version before selecting
latest, so an incompatible version breaks wallet/catalogue reads too.

- `SSISchemaService` uses injected `IEnvironmentProvider`, not a setting/string or build flag.
  Only exact Staging enables the fallback; Production and combined Staging/Production do not.
- Only ACR versions of the configured `SSISchemaFullNameYoID` are eligible. If a fully mapped,
  YoID-compatible default exists, skip whole versions with unsupported attributes and log
  `Stage YoID schema compatibility fallback` at Warning with name/version/id/attribute keys.
  The normal latest selection then chooses the highest compatible version, currently 1.0.
- No partially mapped schema is returned. With no compatible default, the existing strict error
  remains. Custom schemas, JWS, other environments and unrelated mapping failures stay strict.
- The old adapter otherwise resolves latest by name again. Stage YoID issuance therefore carries
  the selected exact ID through the temporary optional request SchemaId and uses the SDK exact-ID
  lookup. This is also guarded by injected exact Staging, YoID and ACR, with returned ID/name checks.
  All other issuance routes retain their previous name-based behaviour.
- No DB migration, schema publication, deletion, credential replay, auth/financial change or config edit.
