### 3. ⚠️ The actual finding: squash-merge, not migration (`bd65a136`, reshaped here)

`bd65a136` introduced context packs on the theory that dead SHAs come from migrating docs mid-flight.
**That theory was wrong, and the evidence is the thing to carry forward.**

`master` is squash-merged — every commit on it is `… (#NNNN)`, one per PR. In the YOM-1271 handoff,
the single surviving citation `b5bfe400` **is** the squashed master commit `(#1910)`; its four dead
siblings were that PR's branch commits. Migration did not kill them. Landing did.

Which means it is aimed at us:

```
Resolvable SHAs cited across docs/work/active:  66
  ...surviving on master:                        5
  ...branch-only (die on squash-merge):         61
```

Every citation in the YOM-1051 docs is branch-only. `70b2ccd`, `0d7a67ba`, `bd4d01c1`, `f051dfd8`,
`08cb6c10a` — all of it dies when this PR lands, in exactly the way Adrian's did.

So the convention was reshaped: prevention over remedy. The README section shrank from 29 lines of
context-pack philosophy to a short **"cite branch SHAs, then re-point them before the PR merges"**
rule; `templates/context-pack.md` stays as the remedy for total loss (a template is inert until
invoked, prose is not); AGENTS.md carries the pre-merge check rather than the philosophy. **Net: less
convention text than `bd65a136` added, and it catches 61 citations instead of zero.**
