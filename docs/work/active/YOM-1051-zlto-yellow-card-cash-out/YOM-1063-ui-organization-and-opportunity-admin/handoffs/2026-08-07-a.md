### Judgement calls, made deliberately

- **`OrganizationRewardPoolsForm` stays a component** even at one field. It owns the schema factory, the `zodResolver`, the server-error-to-field `setError` plumbing, the `aria-describedby`/`aria-invalid` wiring and the clear-the-pool warning. Both homes (the org edit step and the Treasury dialog) would have to duplicate all of that to inline it, and they would drift. The two-column field grid is gone; the field is now full width.
- **Column counts were revisited so nothing is stranded.** `OrganizationRewardStats` keeps its `columns` prop — four stats divide evenly by both 2 and 4 — but its outer wrapper and unused `className` prop went with the second group. Both summary rows (`OrganizationRewardSummaryRow`, `OpportunityRewardSummaryRow`) went to `columns={2}`; at the inherited 4 they would have rendered two stats in a four-column row. `OpportunityRewardContext` falls back to `columns={2}` **only when the payload has no pool**, which is the `OpportunityInfo` case on the opportunity info page — the one caller using the default 4.
- **`summaryTone` simplified**: it was "worst of the two pools" via a `Set` and a priority order; with one pool it is that pool's tone, and the row badge and the stat now share it.

## Gotchas

Carry these forward.

- **There is one reward asset: ZLTO.** No second reward asset, no 2dp reward formatter, no `formatYoma`. If a future ticket wants one, it needs an API contract first — do not reintroduce it in the UI by analogy.
- **"Yoma" is the product name as well as the removed reward.** `yomaInfoURL`, YoID, `Yoma.Core`, page titles and brand copy are untouched and must stay that way. Only *reward* fields went. Grep for `yomaReward`, not `yoma`.

Third occurrence (`4bfeb55c`, the `pendingAwards` rename, and now `yomaRewardTotal`). Delete from the interface **first** and let `tsc` find the readers.
