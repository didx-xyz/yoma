## What Was Done

A claude.design session reviewed the **built** flow through the `/dev/cash-out` gallery rather than
reviewing mockups, and returned a copy sheet plus a design review. Both are now in this folder
([`copy-sheet.md`](../copy-sheet.md), [`design-review-2026-09-14.md`](../design-review-2026-09-14.md)),
each with a header recording what the build did with them. This session applied them.

### The defect it found

**The stepper was ticking step 3 on four screens that mean the opposite** — checking, in progress,
still setting up, and "we couldn't check". `CashOutEntry` resolved the step for the outcome *view*
instead of for a terminal *status*, so a tick — which claims the cash out is resolved — appeared
over a payout that was still moving. `describeOutcome` now carries a `resolved` flag that only
`Completed` / `Cancelled` / `Expired` / `Failed` set.

The dev gallery was hardcoding `stepResolved: true` for every outcome, so it would have hidden the
fix; it derives the flag from `describeOutcome` now, like the flow does. That is the failure mode
the gallery exists to prevent, caught within a day of building it.

### Copy

Every string in `lib/payout/copy.ts`, applied from the sheet. Of its five open decisions, **three
were answered from the API code**: "Estimated" and never "Sent" on a completed payout, because
`PayoutTransaction.Amount` is fixed at initiation and `UpdatePayoutTerminal` never touches it; no
Continue without a preview, because the review step has no estimate to show; and the release wording
is accurate against `TryReleaseReservation` / reconciliation / expiry. The two editorial ones went
the designer's way — **"Check"** over "Review" (the product's other uses are admin-only, a different
reader) and **"Use all"** over "Max".

**One string was refused.** `RESUME_NO_LONGER_ACTIVE` — "This cash out has ended" — re-introduces
the claim removed on 2026-09-11, since a session 404 can originate at the provider and can be
transient. It stays non-committal. The toasts were not built either: nothing renders a Cash Out
toast today, so that is a feature rather than a copy change.

### Structure

- **Hosted dialog**: a fixed-height `role="status"` slot showing "Loading…" then "Taking a while?"
  with the *only* "Open in a new window" control beside it. The second footer button is gone and the
  footer no longer reflows when the prompt appears. A lead line names whose page the frame is, and
  the ✕ tells a screen reader that it also reads the outcome.
- **`Check again`** on still-setting-up and unreadable — the two states that are neither terminal
  nor resumable had no action but "leave".
- **Mobile anchoring** in `CashOutMessageStep`: the message centres in the space it has and the
  actions pin to the bottom, so the primary action is at the end of the thumb's reach rather than
  the middle of the screen. Title up to 22px against a 15px body. Same DOM order.
- **`CashOutDialog` extracted** from `CashOutEntry`, so the state machine is not also a layout and
  the gallery gets the real chrome by construction.
- Smaller: gate links (`Find opportunities`, and a route to fix a wrong country), an inline retry on
  a failed preview, the resume panel's misleading external-link icon removed, and the USD/ZLTO
  labels no longer both say "Amount".

## Gotchas

- **A tick is a claim.** `CashOutStepper`'s `resolved` prop should never be wired to "we are on the
  last step" — only to "the payout reached a terminal status". The same trap is available on any
  future progress indicator here.
- **The gallery can drift.** It renders real components, but anything it passes as a literal
  (`stepResolved`, handlers like `onCheckAgain`) can disagree with what the flow passes. Derive from
  the same helpers where a value is derived in the flow, and pass every handler the flow passes —
  omitting `onCheckAgain` silently showed the wrong primary action for a day.
- **`AMOUNT_COPY.estimateNote` only renders with a ready preview**, so the "why it is an estimate"
  line is absent on the empty and error states by design — it has nothing to qualify there.
- `design/` (the 39 artboards from 2026-09-10) is no longer in this folder and was never committed;
  `feature.md`'s Links section still refers to the canvas as a local file.
