### The bug worth reading first

**`WalletCreationStatus` was a numeric TS enum.** The API serialises every enum as its PascalCase
name — `Startup.cs` registers a strict string enum converter, the Swagger schema says
`"type": "string"`, and the rest of this codebase already compares these fields as strings
(`item.status === "Active"`). So `walletCreationStatus` arrives as `"Created"` while
`WalletCreationStatus.Created` was `2`, and the gate's `!== WalletCreationStatus.Created` was true
for **every** profile: Cash Out would have refused everyone with "Your wallet is still being set
up". The enum was also missing `PendingUsernameUpdate`, so its ordinals were wrong regardless.

It is now a string enum mirroring the C#. Nothing about this fails to compile, and no screenshot
would have shown it — it surfaced from reading the Swagger schema while typing the new payout
status. **Numeric TS enums against this API are latent runtime bugs wherever they appear**; that is
now recorded in the epic's Cross-Area Notes, because it is not a payout problem.

### Wired up (all verified against the code and the Swagger schema, not the message)

- **`profile.payout`** → `{ countryAvailability, active, status, canResume, amount, currency,
  dateCreated }`, active payouts only. The resume panel gained **Started**, and the "still setting
  up" state is now known when the dialog opens rather than discovered by tapping a button that
  cannot work yet.
- **`GET /user/payout/latest`** → `PayoutTransactionInfo`, 404 when the youth has no payout.
  `api/services/payout.ts` takes the 404 as data, like the 503 on `/countries`.
- **`conversionRateZltoPerUsd`** on the conversion preview. **The inference is deleted** —
  `lib/payout/conversion.ts` is now a formatter. The rate line is exact for every amount, including
  the small ones the old interval arithmetic had to hide from.
- **Amount rules are 400s now** (`ValidationException`), so "must be greater than zero" and "must be
  a whole number" land on the field instead of becoming a generic failure. The client guards stay.

### Built

- **The hosted journey is an iframe inside Yoma** (`CashOutHostedStep.tsx`), not a new tab. The
  dialog grows to `md:h-[85vh] md:w-[720px]` for that step only. No DOM inspection, no URL watching,
  no `postMessage` listener — none of those are available or agreed, and none is evidence. A
  discreet **"Open in a new window"** escape hatch remains for a provider or browser that refuses
  framing.
- **Closing it reads the outcome.** ✕ or "I'm done" refreshes the profile, calls the latest
  endpoint, and shows what it says — with a "we couldn't check" state when the read fails.
- **Flow D** (`CashOutOutcomeStep.tsx` + `lib/payout/outcome.ts`): completed, cancelled, **expired
  worded distinctly from cancelled**, failed, neutral in-progress, still-setting-up, and unknown.
  Only completed gets the success treatment. No historical ZLTO figure anywhere — the USD amount and
  the updated wallet carry it instead.

### Also in this session — a CodeQL SSRF finding, unrelated to payout

CI flagged `api/services/marketplace.ts:44`: the `[country]` route segment was interpolated into an
API request path. `getStaticPaths` uses `fallback: "blocking"`, so **any** URL reaches
`getStaticProps`, and the request is then made server-side with the caller's credentials — a
segment containing `..` or an encoded slash could walk onto another endpoint. Encoding alone does
not fix that (`encodeURIComponent("..")` is still `".."`), so `lib/apiPath.ts` validates the shape
first: two letters for a country code, canonical hex for an id. The marketplace page now answers a
malformed country with `notFound` rather than an exception, and the same guard covers the
`[ruleId]` admin path, which has the identical exposure.

Checked in a browser: `/marketplace/WW` and `/marketplace/ZA` still 200, `/marketplace/ZAA` and
`/marketplace/a%2Fb` now 404, and `/marketplace/%2e%2e` never reaches the page at all — Next
collapses it to `/marketplace` before routing.

## Gotchas

- **`Processing` starts when the hosted payout is created, before the youth confirms anything.** So
  no screen names a status: the active trio is one neutral "in progress", and `canResume` decides
  only what is offered. Do not add a "waiting for you" / "processing" distinction off the back of
  `status` — it does not mean that.
- **A 404 from the session endpoint does not mean the payout closed.** It can originate at the
  provider and can be transient, so it routes to the outcome read rather than to a terminal message.
- **Never infer an outcome from the wallet.** A committed reservation and a released one both leave
  `pendingPayout` at zero.
- **`payout.amount` is USD; `zlto.pendingPayout` is ZLTO.** Still two figures for one payout, in two
  units, both called "amount".
- **Do not `POST` to refresh a session** — `GET /user/payout/zlto` issues a fresh one for the same
  payout. A second POST starts a second payout.
- The dev server needs `mise exec -- pnpm dev`: the default `node` on PATH is 20 and corepack's
  pnpm fails on it.
- The API's Swagger schema is served unauthenticated at `/swagger/v3/swagger.json` and is the
  fastest way to check a field's real shape. It is what caught the enum bug.
